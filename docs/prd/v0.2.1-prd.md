# 1. 목적과 범위

v0.2.1은 공용 정적 변환 레지스트리를 8개에서 정확히 24개로 확장한다. 모든 변환은
옵션 없이 하나의 고정된 동작을 가지며, CLI 명령, `--then`, TUI Picker와 Trace는 같은
등록 정의를 사용한다. Recipe, 카테고리, 변환별 옵션, 플러그인, 새 View와 설정형 키맵은
범위에 포함하지 않는다.

기존 입력·출력 한도, 32단계 Pipeline 제한, `TransformFn`, 공개
`pipeline::execute`의 `StrictText` 정책은 유지한다. CLI 내부만 기존 최소 래퍼로
`AllowBinary` 실행을 사용하며, 파이프와 리디렉션은 원시 바이트를 받고 실제 터미널은
기존 안전 출력 검사를 계속 적용한다.

## 1.2 고정 동작

- Base64URL은 RFC 4648 URL 안전 알파벳과 무패딩 인코딩을 사용한다. 디코딩은 ASCII
  space·tab·CR·LF만 무시하고 `=` 및 비정규 후행 비트를 거부한다.
- Base32는 RFC 4648 대문자 알파벳과 정규 패딩을 인코딩하며, 디코딩은 ASCII 대소문자와
  네 종류의 ASCII 공백만 허용한다.
- HTML 인코딩은 텍스트 문맥의 `&`, `<`, `>`만 이스케이프한다. 디코딩은 정확한 세미콜론을
  가진 유효한 이름·숫자 엔터티만 바꾸고 그 외 입력을 그대로 둔다.
- ROT13은 ASCII 영문자만 바꾼다. URL Defang·Refang은 소문자 `http://`, `https://`와
  점 표기를 정해진 IOC 표기로만 상호 변환한다.
- JWT 디코딩은 세 부분 Compact JWS를 정규 Base64URL로 검사하고 Header·Payload의 엄격한
  JSON 객체를 표시한다. Signature는 검증하지 않으며 결과에 정확히 `Signature not verified`
  경고를 포함한다.
- SHA-256·SHA-512는 임의 바이트를 줄바꿈 없는 소문자 16진수로 출력한다. Gzip 압축은
  level 6, `mtime=0`, OS=255의 결정적 한 멤버를 만들고, 해제는 모든 멤버·CRC·후행
  쓰레기를 검증한다.
- 줄 변환은 LF·CRLF를 인식해 LF로 정규화하고 마지막 줄바꿈 존재 여부를 보존한다.
  정렬은 Unicode 코드 포인트 순서이며 중복 제거는 첫 항목을 유지한다.

모든 확장·디코딩·압축 해제와 결과 조합은 단계 출력 한도를 할당 또는 쓰기 중에 확인하고,
오류에는 부분 결과를 제공하지 않는다. 줄 변환은 백만 논리 줄을 넘으면 결과 생성 전에
실패한다.

## 1.3 실행·출력 경계와 고정 의존성

공개 `pipeline::execute`는 `StrictText`를 유지한다. CLI만 crate 내부 최소 실행 경로로
`AllowBinary`를 선택하며, 앞 단계의 이진 결과는 바이트 입력 변환으로 이어질 수 있지만
텍스트 입력 변환 앞에서는 계속 거부된다. 파이프·리디렉션에는 비 UTF-8과 제어 문자를
포함한 결과를 그대로 쓴다. 표준 출력이 실제 터미널이면 `write_result`가 쓰기 전에 결과
전체를 검사해 비 UTF-8 또는 위험 제어 문자를 원자적으로 거부한다. TUI 작업자의 실행
정책과 기존 복사 안전 경계는 변경하지 않는다.

새 고정 의존성은 `data-encoding 2.11.1`, `html-escape 0.2.15`, `sha2 0.11.0`,
순수 Rust 백엔드의 `flate2 1.1.9`다. 버전 범위나 런타임 선택 옵션을 추가하지 않는다.

# 2. TUI 계약

Pipeline의 `f`와 한글 자판 별칭 `ㄹ`은 기존 보관 최종 결과 복원 경로를 호출한다.
Output의 두 키는 무동작이다. 이 변경은 View, 확대, 복사, 스크롤, 상태 수명, 선택 단계
실행과 요청 취소 규칙을 바꾸지 않는다.

Dock, 전체 Help, 작은 화면 Help는 Pipeline에서만 `f Final`을 표시한다. Output Dock과
Help에는 Final을 표시하지 않는다. 도움말은 영문 소문자 키만 표시하며 한글 자판 별칭은
동작만 지원한다.

Output 제목은 다음 형태를 사용한다.

```text
» OUTPUT [SMART] [100 B]
» OUTPUT / STEP 02 [TRACE] [100 B]
```

Ready 상태이고 Artifact가 있으며 제목과 크기 접미사 전체가 패널 폭에 맞을 때만 `[N B]`를
붙인다. Debouncing·Running·Failed·Cancelled 상태, Artifact 부재, 폭 부족에서는 크기
대괄호 전체를 생략하고 기본 제목을 유지한다. View·크기 사이의 구분 기호는 사용하지 않는다.

# 3. 비목표와 호환성

- 역사적 v0.1·v0.2 문서는 수정하지 않는다.
- Boop과 CyberChef는 기능 탐색 자료일 뿐 코드·키맵·레시피 호환 대상으로 삼지 않는다.
- 변환 옵션, 카테고리, Recipe, 유형화 Artifact, 범용 키맵·프레임워크 계층은 추가하지 않는다.
- 기존 클립보드 위험 문자 확인, 원본 Artifact 기반 복사, Trace 비복사 규칙을 유지한다.

# 4. 인수 기준

- 24개 공개 ID가 공용 레지스트리에 한 번씩만 등록되어 CLI, `--then`, Picker, Trace에서
  같은 순서와 정의로 보인다.
- Base64URL·Base32·HTML·JWT·SHA-2·Gzip·IOC·줄 변환은 위 고정 문법과 오류·한도를 따른다.
- 파이프·리디렉션의 이진 출력은 성공하고 실제 터미널의 위험 출력은 원자적으로 거부된다.
- Pipeline `f`·`ㄹ`은 보관 최종 결과를 복원하고 Output `f`·`ㄹ`은 상태를 바꾸지 않는다.
- 제목·Dock·전체 Help·작은 Help·README는 위 TUI 계약과 일치한다.
