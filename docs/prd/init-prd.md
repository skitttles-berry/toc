# 1. 제품 정의

`toc`은 개발 과정에서 자주 발생하는 텍스트와 바이트 변환을 로컬에서 처리하는 명령줄 및 터미널 화면 도구다.

v0.1의 핵심 사용 방식은 두 가지다.

1. **CLI**

   * 파일이나 표준 입력을 변환한다.
   * 여러 변환을 임시 체인으로 연결한다.
   * 최종 결과만 표준 출력에 기록해 셸 파이프라인에서 사용한다.

2. **TUI**

   * 텍스트를 입력하거나 붙여넣는다.
   * 변환 체인을 편집한다.
   * 입력을 변경하지 않고 결과를 실시간으로 미리 본다.
   * 성공한 결과를 운영체제 클립보드로 복사한다.

Boop은 제품 아이디어를 얻기 위한 참고 모델일 뿐이다. Boop의 기능, 구현, 변환 결과, 공개 일정은 `toc`의 요구사항이나 우선순위에 영향을 주지 않는다. v0.1은 Boop 호환성을 보장하지 않으며 Boop 코드를 포팅하지 않는다.

# 2. 문제와 목표

## 2.1 해결할 문제

개발자는 Base64, URL, JSON 변환을 반복해서 수행한다. 이를 위해 서로 다른 웹사이트나 명령을 사용하면 다음 문제가 발생한다.

* 민감한 자료가 외부 서비스로 전달될 수 있다.
* 변환을 여러 번 연결할 때 수작업이 필요하다.
* 명령줄 도구와 대화형 도구의 결과가 달라질 수 있다.
* 대화형 도구의 입력을 직접 덮어쓰면 원본을 잃기 쉽다.

## 2.2 v0.1 목표

* 모든 변환을 네트워크 연결 없이 로컬에서 수행한다.
* CLI와 TUI가 같은 변환 레지스트리와 파이프라인을 사용한다.
* CLI 표준 출력에는 최종 변환 결과만 기록한다.
* TUI는 입력과 미리보기를 분리한 비파괴 작업판으로 동작한다.
* Base64, URL, JSON의 핵심 변환 여섯 개를 명확한 규칙으로 제공한다.
* 입력·출력·체인 크기를 제한해 자원 고갈을 방지한다.
* macOS와 Linux의 `bash`, `zsh`에서 CLI와 TUI를 검증한다.

## 2.3 v0.1 성공 기준

* 파일과 파이프 입력에서 단일 변환과 임시 체인이 동작한다.
* CLI와 TUI에 표현 가능한 동일한 UTF-8 입력과 동일한 체인은 바이트 단위로 같은 결과를 만든다.
* 체인 중간 단계가 실패하면 CLI 표준 출력에 부분 결과를 쓰지 않는다.
* TUI에서 입력, 체인 편집, 미리보기, 결과 복사가 가능하다.
* TUI의 변환 작업이 화면 이벤트 처리를 막지 않는다.
* 위험한 터미널 제어 문자가 화면을 조작하지 못한다.
* 정의된 자원 한도 안에서 잘못된 입력이 패닉을 일으키지 않는다.

# 4. 명령줄 규약

## 4.1 명령 구조

```text
toc
toc --help
toc --version
toc --list
toc <transform-id> [--input <PATH>] [--then <transform-id>]...
toc tui
```

`run`, `transform`, `chain`, `script`, `doctor` 같은 상위 명령은 두지 않는다.

예:

```bash
printf '%s' 'hello' | toc base64-encode
toc format-json --input data.json
printf '%s' '%7B%22a%22%3A1%7D' |
  toc url-decode \
    --then format-json
```

## 4.2 기본 명령

인자 없이 `toc`을 실행하면 다음 내용을 포함한 간단한 도움말을 표준 출력에 기록하고 코드 `0`으로 종료한다.

* 사용 형식
* `--list`
* `toc <transform-id> --help`
* `toc tui`

인자 없이 TUI를 자동 실행하지 않는다.

## 4.3 조회 명령

* `toc --help`: 전체 도움말
* `toc --version`: 제품 버전
* `toc --list`: 등록된 여섯 변환의 식별자, 표시 이름, 한 줄 설명
* `toc <transform-id> --help`: 해당 변환의 입력 조건과 고정 동작

변환 식별자는 CLI의 공개 호환성 규약이다. 공개 후 이름을 변경하지 않는다. 예약 명령인 `tui`와 충돌하는 식별자는 등록할 수 없다.

## 4.4 입력

허용하는 입력원은 다음 두 가지다.

1. `--input <PATH>`
2. 파이프로 전달된 표준 입력

정확히 하나만 허용한다.

* 파일과 파이프 입력이 동시에 존재하면 코드 `2`의 사용법 오류를 반환한다.
* `--input`이 없고 표준 입력이 터미널이면 대기하지 않고 코드 `2`를 반환한다.
* 입력을 읽기 전에 표준 출력을 열거나 결과를 쓰지 않는다.
* `--text`는 셸 기록과 프로세스 인자에 민감한 내용이 남을 수 있으므로 제공하지 않는다.

## 4.5 임시 체인

```bash
printf '%s' 'JTdCJTIyYSUyMiUzQTElN0Q=' |
  toc base64-decode \
    --then url-decode \
    --then format-json
```

실행 규칙:

1. 첫 변환 뒤에 `--then <transform-id>`를 반복해 단계를 추가한다.
2. 같은 변환을 여러 번 추가할 수 있다.
3. 단계는 작성 순서대로 실행한다.
4. 변환별 옵션과 단계별 옵션은 없다.
5. 최대 단계 수는 32개다.
* CLI는 첫 변환과 `--then` 합계를 입력 파일이나 표준 입력보다 먼저 검증한다.
* 단계 초과와 입력 오류가 동시에 있으면 단계 초과 오류가 우선한다.
6. 한 단계가 실패하면 이후 단계를 실행하지 않는다.
7. 모든 단계가 성공한 뒤에만 최종 결과를 표준 출력에 기록한다.

## 4.6 출력

성공한 CLI 변환의 표준 출력에는 최종 결과 바이트만 기록한다.

* 안내, 경고, 오류는 표준 오류에만 기록한다.
* 결과 끝에 줄바꿈을 임의로 추가하지 않는다.
* ANSI 색상과 장식용 제어 코드를 출력하지 않는다.
* `--output`, `--newline`, `--json-envelope`, `--color`는 제공하지 않는다.
* 파일 출력은 셸의 출력 재지정을 사용한다.

다음 프로그램이 먼저 종료해 발생한 끊어진 파이프는 오류 메시지 없이 정상 종료한다. 그 밖의 표준 출력 쓰기 실패는 코드 `5`를 반환한다.

### 터미널 제어 문자 보호

변환 결과가 실제 터미널로 직접 출력될 때 위험한 제어 문자가 포함되어 있으면 결과를 출력하지 않는다.

* 탭, LF, CR은 허용한다.
* 널, 이스케이프, 그 밖의 C0·C1 제어 문자는 위험 문자로 취급한다.
* 표준 오류에 안전하게 이스케이프한 제한 길이 미리보기와 해결 방법을 표시한다.
* 표준 출력이 파이프나 파일이면 원본 결과를 그대로 쓴다.

이 정책은 파이프라인의 정확성을 유지하면서 터미널 제어 시퀀스 삽입을 막는다.

## 4.7 종료 코드

| 코드 | 의미 |
|---:|---|
| `0` | 변환, 도움말, 목록 출력 성공 |
| `1` | TUI 또는 일반 실행 환경 오류 |
| `2` | 잘못된 명령, 옵션, 입력원 조합 |
| `3` | 입력 읽기 실패 또는 입력 한도 초과 |
| `4` | 변환 실패 또는 단계 출력 한도 초과 |
| `5` | 표준 출력 쓰기 실패 |
| `130` | 사용자 인터럽트 |

오류 메시지는 가능한 경우 다음 정보를 포함한다.

* 실패한 체인 단계 번호
* 변환 식별자
* 입력 위치
* 원인
* 사용자가 취할 수 있는 조치

입력 원문과 전체 결과를 오류 메시지에 포함하지 않는다. 파일 경로와 외부 문자열의 제어 문자는 안전하게 이스케이프한다.

# 5. 공용 파이프라인

## 5.1 자료 모델

파이프라인은 바이트 배열을 전달한다.

```rust
pub struct Payload {
    pub bytes: Vec<u8>,
}
```

변환별 입력 조건:

| 변환 | 허용 입력 |
|---|---|
| `base64-encode` | 임의 바이트 |
| 나머지 다섯 변환 | 유효한 UTF-8 |

`base64-decode`는 내부적으로 바이트를 만들지만, 결과가 유효한 UTF-8일 때만 성공한다. 따라서 v0.1의 성공한 변환 결과는 모두 UTF-8이며 TUI에서 문자열로 다룰 수 있다.

## 5.2 변환 등록

변환은 메타데이터와 실행 함수 포인터를 가진 정적 목록에 등록한다.

필수 메타데이터:

* 영구 식별자
* 표시 이름
* 한 줄 설명
* 입력 조건
* 실행 함수

등록 목록은 다음을 시험한다.

* 등록 개수가 정확히 6개다.
* 식별자가 중복되지 않는다.
* 식별자가 예약 명령과 충돌하지 않는다.
* 모든 항목에 이름과 설명이 있다.
* 모든 항목에 최소 한 개의 정상 및 오류 시험이 있다.

새 변환은 실행 함수와 등록 항목을 추가하는 방식으로 확장한다. v0.1에는 플러그인 인터페이스, 자동 등록 매크로, 별도 변환 크레이트를 만들지 않는다.

## 5.3 실행 규칙

1. 현재 단계가 입력 조건을 검증한다.
2. 성공 결과를 다음 단계 입력으로 전달한다.
3. 단계별 출력 한도를 즉시 검증한다.
4. 한 단계라도 실패하면 파이프라인 전체를 실패로 처리한다.
5. CLI는 성공 전까지 표준 출력에 아무것도 쓰지 않는다.
6. TUI의 비활성 단계는 건너뛴다.
7. 중간 결과 캐시는 사용하지 않는다.

CLI와 TUI는 같은 등록 목록과 실행 함수를 사용한다. TUI 전용 표시는 변환 결과와 분리한다.

## 5.4 자원 한도

| 구분 | CLI | TUI |
|---|---:|---:|
| 최대 입력 | 64 MiB | 1 MiB |
| 각 단계 최대 출력 | 256 MiB | 64 MiB |
| 최대 체인 단계 | 32개 | 32개 |
| 최대 입력 줄 수 | 해당 없음 | 65,536줄 |
| 실행 취소·다시 실행 이력 | 해당 없음 | 8개 |

* 어느 단계든 한도를 넘으면 전체 실행이 실패한다.
* 제한 변경 옵션과 무제한 옵션은 제공하지 않는다.
* 입력과 출력 용량은 원본 바이트 길이로 계산한다.
* TUI는 전체 결과를 보관하되 렌더링할 때 현재 보이는 범위만 처리해 큰 결과가 매 화면 갱신마다 복사되지 않게 한다.

# 6. 변환 명세

## 6.1 공통 규칙

* 변환 식별자와 동작은 CLI와 TUI에서 같다.
* 변환 결과 뒤에 줄바꿈을 자동으로 추가하지 않는다.
* 오류는 손실 치환이나 부분 성공으로 숨기지 않는다.
* 운영체제 로캘과 기본 줄바꿈에 의존하지 않는다.

## 6.2 `base64-encode`

표시 이름: `Base64 Encode`

동작:

* 임의 바이트 입력을 허용한다.
* RFC 4648 표준 Base64 문자표를 사용한다.
* 정규 `=` 패딩을 항상 출력한다.
* 결과는 ASCII이며 끝 줄바꿈을 추가하지 않는다.

## 6.3 `base64-decode`

표시 이름: `Base64 Decode`

동작:

* 표준 Base64 문자표만 허용한다.
* 입력의 ASCII 공백, 탭, CR, LF는 제거한 뒤 검증한다.
* 누락되거나 잘못된 패딩을 허용하지 않는다.
* 사용되지 않는 마지막 비트까지 정규 형식으로 검증한다.
* 디코딩 결과가 유효한 UTF-8일 때 문자열 그대로 반환한다.

디코딩 결과가 유효한 UTF-8이 아니면 다음과 같이 처리한다.

* 변환 오류와 코드 `4`를 반환한다.
* CLI 표준 출력은 비운다.
* 표준 오류에는 최대 64바이트의 16진수 미리보기만 표시한다.
* 생략된 바이트가 있으면 생략 사실과 전체 바이트 수를 표시한다.
* 손실 UTF-8 치환은 하지 않는다.

URL 안전 Base64와 패딩 자동 보정은 지원하지 않는다.

## 6.4 `url-encode`

표시 이름: `URL Encode`

전체 URL이 아닌 RFC 3986 주소 구성요소를 인코딩한다.

* 영문자, 숫자, `-`, `.`, `_`, `~`만 그대로 유지한다.
* 나머지는 UTF-8 바이트 기준 대문자 `%HH`로 인코딩한다.
* 공백은 `+`가 아니라 `%20`으로 인코딩한다.
* 기존 `%`도 `%25`로 인코딩한다.
* 입력은 유효한 UTF-8이어야 한다.

## 6.5 `url-decode`

표시 이름: `URL Decode`

* `%HH`는 대소문자 16진수를 모두 허용해 바이트로 디코딩한다.
* `+`는 공백으로 바꾸지 않고 그대로 유지한다.
* 불완전하거나 16진수가 아닌 `%` 형식은 오류다.
* 결과 바이트가 유효한 UTF-8이 아니면 변환 오류를 반환한다.
* 유효하지 않은 UTF-8의 오류 미리보기는 Base64와 같은 최대 64바이트 16진수 정책을 사용한다.

전체 URL 보존과 HTML 폼 방식은 지원하지 않는다.

## 6.6 `format-json`

표시 이름: `JSON Prettify`

* 엄격한 표준 JSON만 허용한다.
* 객체, 배열, 문자열, 숫자, 불리언, 널을 최상위 값으로 허용한다.
* 주석, 후행 쉼표, UTF-8 BOM은 오류다.
* 최대 객체·배열 중첩 깊이는 128단계다.
* 최상위 객체나 배열을 깊이 1로 계산한다.
* 모든 중첩 객체에서 중복 키를 오류로 처리한다.
* 중복 여부는 디코딩한 키를 기준으로 판단한다. 따라서 `"a"`와 `"\u0061"`은 같은 키다.
* 객체 키 순서는 입력 순서를 유지한다.
* 공백 2칸으로 들여쓴다.
* 구조를 위해 추가하는 줄바꿈은 항상 LF다.
* 마지막 줄바꿈은 추가하지 않는다.

문법 검증 후 문자열 밖의 구조 공백만 다시 배치한다. 문자열, 숫자, 키워드 토큰의 원문 표기는 그대로 복사한다.

```text
"\u0061" → "\u0061"
1e2       → 1e2
1.00      → 1.00
```

## 6.7 `minify-json`

표시 이름: `JSON Minify`

문법, 깊이, 중복 키, 순서, 토큰 보존 규칙은 `format-json`과 같다.

* 문자열 밖의 불필요한 공백, 탭, CR, LF만 제거한다.
* JSON 문자열 내부의 문자와 이스케이프 표기는 바꾸지 않는다.
* 마지막 줄바꿈을 추가하지 않는다.

## 6.8 JSON 구현 제약

JSON 변환은 다음 두 단계를 분리한다.

1. `serde_json` 기반 엄격한 문법·깊이·중복 키 검증
2. 문자열 상태를 인식하는 작은 토큰 스캐너로 구조 공백만 재배치

파싱한 값을 다시 직렬화하지 않는다. 이 방식으로 키 순서, 이스케이프, 숫자 표기를 보존한다.

# 7. TUI 요구사항

## 7.0 후속 승인 설계와의 관계

2026-07-31에 `docs/superpowers/specs/2026-07-31-toc-tui-workbench-design.md`가 후속 승인되었고 기능 구현과 macOS·Linux 실제 TUI·클립보드 통합 검증을 완료했다. 따라서 다음 기존 TUI 규약은 새 설계로 대체된다.

* 120열 미만 전체를 단일 패널로 표시하는 레이아웃
* 모든 Input과 Chain 변경에 고정 200밀리초 지연을 적용하는 실행 정책
* 중간 성공 결과를 표시하지 않는 정책
* 디코딩 결과가 비 UTF-8이면 TUI Pipeline도 실패하는 정책
* 단계 Inspector, Help Overlay와 패널 Zoom을 제공하지 않는 범위

TUI 작업판 규약은 후속 설계가 현재 기준이다. 아래 TUI 절은 반영된 작업판 동작을 함께 기록하며, 비파괴 Input, 터미널 안전성, 자원 한도, 종료 복구와 CLI 규약은 유지한다.

## 7.1 실행 조건

```bash
toc tui
```

* `toc tui`만 유효하다.
* 추가 명령이나 옵션이 있으면 코드 `2`의 사용법 오류를 반환한다.
* 표준 입력과 표준 출력이 모두 실제 터미널일 때만 시작한다.
* 파이프, 출력 재지정, 비대화형 환경에서는 원인을 표준 오류에 표시하고 코드 `1`로 종료한다.
* 항상 빈 입력과 빈 체인으로 시작한다.
* 파일, 표준 입력, 이전 세션을 자동으로 불러오지 않는다.

## 7.2 비파괴 작업판

TUI는 다음 세 영역으로 구성한다.

1. **Input:** 사용자가 편집하는 원본
2. **Output:** 최종 또는 선택 단계의 읽기 전용 결과, Trace나 오류
3. **Pipeline:** 순서가 있는 변환 단계

규칙:

* Pipeline 실행은 Input을 변경하지 않는다.
* 빈 Pipeline은 Input을 그대로 Output에 표시한다.
* Output을 Input으로 확정하는 기능은 없다.
* 종료 시 Input, Output, Pipeline을 저장하지 않는다.

## 7.3 화면 배치

### 너비 120열 이상

Pipeline을 왼쪽 28~42열에 표시하고 오른쪽은 Input 42%, Output 58%의 세로 구조로 표시한다.

```text
┌─ Pipeline ────────┬─ Input ─────────────────────────────────────┐
│ 1 URL Decode      │                                             │
│ 2 JSON Prettify   ├─ Output — FINAL — Smart ────────────────────┤
│                   │                                             │
└───────────────────┴─────────────────────────────────────────────┘
```

### 너비 90~119열

같은 분할 구조를 유지하되 Pipeline을 28~32열로 줄이고 부가 정보를 숨긴다.

### 너비 40~89열

Pipeline, Input, Output을 한 번에 하나씩 탭으로 표시한다.

### 너비 40열 미만 또는 높이 10행 미만

편집 영역 대신 터미널 크기를 늘리라는 안내만 표시한다.

높이가 부족하면 내용 행을 우선 확보하고 Step Summary, Navigation, 낮은 우선순위 Context 도움말 순서로 숨긴다.

## 7.4 입력 편집

`tui-textarea-2`를 `tui` 모듈 안에서 직접 사용한다.

* 여러 줄 편집
* 유니코드 커서 이동
* 화면 감싸기와 스크롤
* 실행 취소와 다시 실행
* bracketed paste

입력은 UTF-8 바이트 기준 1 MiB와 65,536줄을 넘는 편집 또는 붙여넣기를 반영하지 않는다. 실행 취소와 다시 실행 이력은 8개로 제한한다.

검색, 다중 선택, 문법 강조 기능은 활성화하지 않는다. 별도 편집기 인터페이스도 만들지 않는다.

### 입력 제어 문자

화면에 보이는 값과 실제 변환 입력을 일치시킨다.

* 일반 문자열은 그대로 유지한다.
* 탭과 줄바꿈은 실제 편집 문자로 유지한다.
* CRLF와 단독 CR은 LF로 정규화한다.
* 널, 이스케이프, 그 밖의 위험한 제어 문자는 붙여넣을 때 `\x00`, `\x1b` 같은 표시 가능한 문자열로 치환한다.
* 치환이 발생하면 상태 표시줄에 치환 개수만 표시한다.
* 원본 제어 바이트를 그대로 처리해야 하면 CLI를 사용한다.

## 7.5 변환 선택과 체인 편집

Operation Palette는 등록된 여덟 변환만 표시한다.

* 이름 또는 식별자의 대소문자 무시 단순 부분 문자열로 필터링한다.
* 선택 항목의 설명, 입력 조건과 출력 힌트를 표시한다.
* 퍼지 검색, 카테고리, 태그, 최근 사용 순위는 제공하지 않는다.
* 선택한 변환은 활성 상태로 체인 끝에 추가한다.
* 같은 변환을 여러 번 추가할 수 있다.
* 단계 삭제, 위아래 이동, 활성화·비활성화를 지원한다.
* 마우스 드래그, 단계 복제, 옵션 편집은 제공하지 않는다.

## 7.6 키 바인딩

| 키 | 동작 |
|---|---|
| `Ctrl+P` | Operation Palette 열기 |
| `Tab`, `Shift+Tab` | Input, Output, Pipeline 사이 이동 |
| `F1`, Input 이외의 `?` | 현재 패널 도움말 |
| Output의 `v`, `V` | 다음·이전 View |
| Output의 `p`, `f` | 선택 단계 결과 요청·최종 결과 복귀 |
| Output의 `Enter`, `y` | 복사 가능한 전체 결과를 운영체제 클립보드로 복사 |
| Pipeline의 `↑`·`↓`·`j`·`k` | 선택 단계 이동 |
| Pipeline의 `Space` | 선택 단계 활성화·비활성화 |
| Pipeline의 `Delete`, `d` | 선택 단계 삭제 |
| Pipeline의 `Shift+↑`·`Shift+↓`·`J`·`K` | 선택 단계 순서 변경 |
| Pipeline의 `Enter` | 읽기 전용 Inspector |
| Pipeline 또는 Output의 `z` | 현재 패널 Zoom |
| `Esc` | Modal·Zoom 닫기 또는 현재 실행 요청 취소 |
| `Ctrl+Q` | 종료 또는 폐기 확인 |
| `Ctrl+C` | 코드 `130`으로 강제 종료 |
| Input의 나머지 키 | `tui-textarea-2` 기본 편집 동작 |

사용자 키 설정과 마우스 조작은 제공하지 않는다.

## 7.7 실시간 미리보기

* Input 또는 Pipeline 변경 후 입력이 256 KiB 이하이면 50밀리초, 초과하면 200밀리초 동안 추가 변경이 없을 때 실행한다.
* 변환은 화면 이벤트 처리와 분리된 작업 스레드 하나에서 실행한다.
* 결과 채널이 종료되면 작업자를 자동 재시작하지 않고 안전한 TUI 오류로 종료하며 기존 터미널 복구 경로를 실행한다.
* 요청은 증가하는 세대 번호로 식별한다.
* 실행 중 새 요청이 발생하면 대기 슬롯에는 최신 요청 하나만 유지한다.
* 실행 중인 내장 변환 하나는 강제 중단하지 않지만 단계 사이에서 취소를 확인하고, 오래된 결과는 폐기한다.
* 실행 중에는 상태를 표시하고 직전 결과는 숨긴다.
* 단계별 결과 캐시는 사용하지 않는다.
* `p`는 선택 단계까지 즉시 재계산하고, `f`는 보관된 최종 결과를 재실행 없이 복원한다.

파이프라인이 실패하면 다음처럼 처리한다.

* Output에 실패 단계와 안전한 오류만 표시한다.
* 이전 성공 결과와 중간 결과를 숨긴다.
* 결과 복사를 비활성화한다.
* Input이나 Pipeline 수정 후 전체 체인이 성공하면 Output과 복사를 복구한다.

## 7.8 결과 표시와 복사

* 기본 Smart View는 UTF-8 결과를 Text, 비 UTF-8 결과를 Hex, 실행 오류를 Trace로 표시한다.
* 사용자가 고른 Text·Hex·Trace View는 다시 Smart를 고를 때까지 유지한다.
* 일반 문자열, 탭과 줄바꿈은 그대로 표시한다.
* 터미널을 제어할 수 있는 문자는 `\x1b` 같은 이스케이프 형태로 표시한다.
* 표시용 이스케이프는 내부 원본 결과를 변경하지 않는다.
* 줄바꿈 없는 긴 행은 그래핌과 표시 폭을 기준으로 Viewport 안에서 자동 줄바꿈한다. 이 줄바꿈은 화면 표시 전용이며 원본 Artifact와 클립보드 내용에는 추가하지 않는다.
* UTF-8 결과는 View와 무관하게 정규화·손실 변환 없이 원본 문자열 전체를 복사한다.
* 비 UTF-8 결과는 View와 무관하게 공백 없는 소문자 Hex로 복사하고 `Copied as Hex`를 표시한다.
* Trace, 실패, 취소, 실행·지연 중, 오래되거나 없는 결과는 복사하지 않는다.
* UTF-8 원본 결과에 위험한 제어 문자가 있으면 이미 만든 payload를 확인 창이 소유하며, 승인 시 같은 payload를 이동한다.
* 복사 길이 계산, 메모리 할당이나 운영체제 클립보드 쓰기가 실패하면 화면 안에 안전하게 표시하고 Input, Pipeline과 Output을 유지한다.
* 클립보드 내용과 변환 결과는 로그에 기록하지 않는다.

Linux에서는 X11·XWayland와 라이브러리가 지원하는 Wayland 자료 제어 환경을 대상으로 한다. `toc` 종료 후 클립보드 내용 유지 여부는 데스크톱 환경이나 클립보드 관리자에 의존한다. 이를 위해 별도 백그라운드 프로세스를 만들지 않는다.

## 7.9 종료와 터미널 복구

* Input이 비어 있으면 종료 명령에서 즉시 종료한다.
* Input이 있으면 폐기 확인 창을 표시한다.
* 사용자가 확인한 뒤에만 정상 종료한다.
* 강제 인터럽트, 패닉, 터미널 오류에서도 raw mode, 대체 화면, bracketed paste 설정을 복구한다.
* 종료 확인과 오류 로그에 Input이나 Output 내용을 포함하지 않는다.

## 7.10 접근성과 표시 안전성

* 성공, 실행 중, 오류, 비활성 상태를 색상만으로 구분하지 않는다.
* 16색 터미널에서도 읽을 수 있는 기본 색상을 사용한다.
* `NO_COLOR` 환경 변수가 있으면 장식 색상을 비활성화한다.
* 외부 문자열의 ANSI 제어 코드를 터미널에 그대로 전달하지 않는다.

# 8. 기술 구조

## 8.1 저장소 구조

v0.1은 단일 Cargo 패키지와 단일 실행 파일로 구현한다.

```text
toc/
├── Cargo.toml
├── Cargo.lock
├── rust-toolchain.toml
├── src/
│   ├── main.rs
│   ├── lib.rs
│   ├── cli.rs
│   ├── pipeline.rs
│   ├── tui.rs
│   ├── tui/
│   │   ├── render.rs
│   │   ├── state.rs
│   │   ├── views.rs
│   │   └── worker.rs
│   └── transforms/
│       ├── mod.rs
│       ├── base64.rs
│       ├── url.rs
│       ├── json.rs
│       └── hex.rs
├── tests/
└── docs/
```

책임:

* `main.rs`: 인자 해석 결과 실행, 표준 입출력, 종료 코드
* `lib.rs`: 공용 모듈 노출
* `cli.rs`: 명령 정의와 입력원 검증
* `pipeline.rs`: 체인 검증, 한도 검사, `StrictText`·`AllowBinary` 순차 실행 보고서
* `tui.rs`: 터미널 수명, 이벤트 루프와 클립보드 외부 효과
* `tui/state.rs`: App 상태, 키 입력과 상태 전이
* `tui/worker.rs`: 지연 실행, 최신 요청과 Pipeline 작업
* `tui/render.rs`: 반응형 배치, 패널, Overlay와 상태 표시
* `tui/views.rs`: Smart 판정과 Text·Hex·Trace의 제한된 범위 렌더링
* `transforms`: 여덟 변환과 정적 등록 목록

파일이 실제로 읽기 어려워질 때만 하위 모듈을 더 나눈다. v0.1에는 Cargo Workspace나 별도 내부 크레이트를 만들지 않는다.

## 8.2 의존성

| 라이브러리 | 용도 |
|---|---|
| `clap` | 명령과 도움말 |
| `ratatui` | 화면 배치와 렌더링 |
| `crossterm` | 터미널 이벤트, raw mode, bracketed paste |
| `tui-textarea-2` | 여러 줄 입력 편집 |
| `unicode-segmentation` | 확장 그래핌 경계 |
| `unicode-width` | 터미널 셀 폭 |
| `arboard` | 운영체제 클립보드 |
| `base64` | 표준 Base64 |
| `serde`, `serde_json` | 엄격한 JSON 문법과 중복 키 검증 |

추가 원칙:

* URL 인코딩과 JSON 공백 재배치는 범위가 작으므로 직접 구현한다.
* 비동기 런타임, 퍼지 검색, 설정, 스크립트 의존성은 추가하지 않는다.
* 애플리케이션이므로 `Cargo.lock`을 커밋한다.
* 구현 시작 시 호환되는 최신 안정 라이브러리를 선택하고 잠금 파일로 고정한다.

## 8.3 Rust 도구 체인

* Rust 2024 Edition을 사용한다.
* v0.1은 최신 안정 Rust를 사용한다.
* 2026-07-29 기준 최신 안정판인 Rust `1.97.1`을 `rust-toolchain.toml`에 고정한다.
* 도구 체인을 올릴 때 빌드와 전체 시험을 통과한 뒤 고정 버전을 변경한다.
* v0.1에서는 별도 최소 지원 Rust 버전을 약속하지 않는다.

## 8.4 확장 원칙

* CLI와 TUI가 공용 파이프라인에만 의존하도록 모듈 경계를 유지한다.
* 새 변환은 기존 실행 함수 형식과 정적 등록 목록을 재사용한다.
* 두 번째 독립 소비자나 빌드 분리 요구가 생길 때만 Workspace를 검토한다.
* 실제 사용자 플러그인 요구가 생길 때만 플러그인 인터페이스를 설계한다.
* 현재 사용하지 않는 인터페이스, 팩터리, 편집기 어댑터는 만들지 않는다.

# 9. 보안과 개인정보

## 9.1 로컬 우선

* 변환 과정에서 네트워크에 연결하지 않는다.
* 텔레메트리와 업데이트 확인을 제공하지 않는다.
* 계정, 로그인, 클라우드 저장을 제공하지 않는다.
* TUI 입력, 결과, 체인을 디스크에 저장하지 않는다.
* 오류 보고서나 로그에 입력·출력·클립보드 본문을 넣지 않는다.

## 9.2 신뢰 경계

* 파일, 표준 입력, 붙여넣기, 파일 경로, 변환 식별자는 신뢰하지 않는 입력으로 취급한다.
* 입력 크기, 단계 수, 단계 출력 크기, JSON 깊이를 변환 전에 또는 처리 중 검증한다.
* 잘못된 UTF-8을 손실 변환하지 않는다.
* 중복 JSON 키를 조용히 덮어쓰지 않는다.
* CLI가 터미널에 위험한 제어 문자를 직접 쓰지 않는다.
* TUI 입력과 결과의 위험한 제어 문자를 안전한 표시로 정규화하거나 이스케이프한다.
* 오류는 입력 전체가 아닌 위치와 제한된 미리보기만 제공한다.

## 9.3 민감한 입력

`--text`를 제공하지 않는다. 명령 인자에 토큰이나 개인정보를 넣으면 셸 기록과 프로세스 목록에 노출될 수 있기 때문이다.

민감한 값은 표준 입력이나 접근 권한이 제한된 파일로 전달하도록 문서화한다.

## 9.4 클립보드

* 클립보드 읽기는 하지 않는다.
* 사용자가 Output에서 명시적으로 복사할 때만 쓴다.
* 유효한 UTF-8 원문에 위험한 제어 문자가 포함되면 이미 만든 복사 payload를 확인 창이 소유하고 승인 후 이동한다.
* 비 UTF-8 결과는 검사된 길이의 공백 없는 소문자 Hex로만 복사한다.
* 복사 실패 시 Input, Pipeline, Artifact나 Trace를 삭제하지 않는다.

# 10. 품질 요구사항

## 10.1 기능 품질

* 여덟 변환은 명세된 정상, 오류, 경계 입력에서 결정적으로 동작한다.
* 모든 활성 단계의 출력이 유효한 UTF-8인 공용 입력 범위에서는 CLI와 TUI의 같은 체인이 같은 바이트를 반환한다.
* CLI는 단계별 `StrictText`, TUI는 최종 바이트를 보존하는 `AllowBinary` 정책을 사용한다.
* 내장 변환의 잘못된 입력으로 패닉이 발생하지 않는다.
* 파이프라인 실패는 부분 표준 출력을 남기지 않는다.
* TUI는 변환 실행 중에도 키 입력, 화면 갱신, 종료 요청을 처리한다.
* TUI 종료 시 터미널 상태를 복구한다.

## 10.2 성능 정책

v0.1에는 측정 근거가 없는 시작 시간, 처리 시간, 메모리 숫자 목표를 두지 않는다.

* 입력·출력·단계·JSON 깊이 한도는 필수다.
* TUI 실행 지연은 256 KiB 이하 50밀리초, 초과 입력 200밀리초다.
* 변환은 TUI 이벤트 처리 스레드에서 실행하지 않는다.
* 첫 구현 후 Release 빌드 측정값을 기준 자료로 기록한다.
* 실제 사용자 체감 문제가 확인되면 재현 가능한 장비와 자료를 정의한 뒤 목표값을 추가한다.

# 12. v0.1 인수 기준

다음 조건을 모두 충족해야 v0.1로 판단한다.

2. 단일 Cargo 패키지에서 하나의 `toc` 실행 파일이 만들어진다.

10. JSON 토큰 원문, 키 순서, 중복 키 거부, 깊이 제한이 시험으로 고정된다.
11. `toc tui`가 빈 비파괴 작업판을 열고 추가 인자를 거부한다.
12. TUI에서 체인 편집, 실시간 미리보기, 결과 복사가 가능하다.
13. TUI 오류 상태에서 오래된 결과를 복사할 수 없다.
14. 위험한 제어 문자가 CLI와 TUI 화면을 조작할 수 없다.
15. 종료와 오류 경로에서 터미널 설정이 복구된다.
16. macOS와 Linux의 `bash`, `zsh`에서 CLI와 TUI를 검증한다.
17. `cargo fmt`, `cargo clippy`, `cargo test`가 모두 통과한다.
18. 소스 저장소에서 `cargo install --locked --path .` 설치를 검증한다.

# 14. 후속 아이디어

아래 항목은 폐기한 요구사항이 아니라 v0.1에서 의도적으로 제외한 아이디어다. 실제 사용자 요구, 시험 벡터, 보안 경계가 확인될 때 우선순위를 다시 정한다. v1.0 범위와 일정도 그때 별도로 정의한다.

## 14.1 추가 변환

v0.1의 여섯 변환을 제외한 기존 후보는 다음과 같다.

### 인코딩·디코딩·진법

```text
ascii-to-hex
hex-to-ascii
binary-to-decimal
decimal-to-binary
decimal-to-hex
hex-to-decimal
url-entities-encode
url-entities-decode
html-encode
html-decode
html-encode-all
jwt-decode
rot13
url-defang
url-refang
```

JWT는 서명 미검증을 명확히 경고해야 한다. URL Defang은 보안 경계가 아닌 표시 보조 기능으로만 정의해야 한다.

### 데이터 형식과 포맷팅

```text
csv-to-json
json-to-csv
json-to-yaml
yaml-to-json
json-to-query-string
query-string-to-json
php-unserialize
format-css
format-sql
format-xml
minify-css
minify-sql
minify-xml
sort-json
```

추가 전에 CSV 열 불일치, YAML 별칭·태그·다중 문서, XML 텍스트 공백, SQL 방언, PHP 객체 비인스턴스화 정책을 명세해야 한다.

### 문자열

```text
add-slashes
remove-slashes
camel-case
kebab-case
snake-case
start-case
upcase
downcase
deburr
replace-smart-quotes
reverse-string
trim
collapse-lines
markdown-quote
lorem-ipsum
sponge-case
```

추가 전에 Unicode 문자 단위, 대소문자 확장, 줄바꿈 보존, 공백 범위, 난수 seed를 명세해야 한다.

### 줄·목록·통계

```text
count-characters
count-lines
count-words
remove-duplicate-lines
reverse-lines
shuffle-lines
sort-lines
natural-sort-lines
sum-all
```

추가 전에 바이트·Unicode scalar·grapheme 기준, 정렬 로캘, 중복 순서, 숫자 형식, 난수 seed를 명세해야 한다.

### 날짜·시간

```text
date-to-timestamp
date-to-utc
```

추가 전에 시간대 없는 입력의 기본값, 초·밀리초·마이크로초 단위, 자동 추론 허용 여부를 명세해야 한다.

### 해시

```text
md5
sha1
sha256
sha512
```

MD5와 SHA-1은 보안 목적에 부적합한 레거시 알고리즘으로 표시해야 한다.

### 모바일 문자열과 기타

```text
android-strings-to-ios
ios-strings-to-android
evaluate-javascript
fish-path-hex
hex-to-rgb
test-script
```

모바일 문자열 변환은 복수형·서식 지정자·이스케이프의 손실을 경고해야 한다. `test-script`는 사용자 기능이 아니라 개발 진단 기능 후보로만 취급한다.

## 14.2 현재 변환의 확장

* URL 안전 Base64
* Base64 무패딩 모드와 패딩 자동 보정
* Base64 바이너리 원본 출력
* 바이너리 16진수·이스케이프 미리보기
* 전체 URL 보존 인코딩
* HTML 폼 방식의 `+` 공백 처리
* JSON 키 정렬
* JSON 들여쓰기 폭 옵션
* JSON 토큰 정규화 또는 재직렬화 모드

추가 조건은 고정 동작만으로 해결할 수 없는 실제 사례와 모호하지 않은 옵션 문법이 존재하는 것이다.

## 14.3 CLI 확장

* `--output` 원자적 파일 쓰기와 덮어쓰기 보호
* `--newline`
* `--json-envelope`
* 입력·출력 한도 변경 옵션
* `--input -`
* 변환별 명시적 옵션
* 복잡한 단계별 옵션 문법
* `bash`, `zsh` 자동 완성
* Man page

`--text`는 민감한 내용 노출 위험 때문에 단순 편의 기능으로 다시 추가하지 않는다. 안전한 사용 사례와 경고만으로 충분한지 별도 보안 검토가 필요하다.

## 14.4 저장 체인과 설정

* 이름 있는 체인 저장·불러오기
* TOML 체인 형식과 버전
* CLI와 TUI 공유
* 가져오기·내보내기
* 체인 마이그레이션
* 최근 사용 목록
* 사용자 키 바인딩

저장 기능을 추가할 때는 원자적 쓰기, 파일 권한, 손상 복구, 스키마 호환성을 먼저 설계한다.

## 14.5 TUI 확장

* Output을 Input으로 확정
* 실행 취소 기록과 체인 유지 확정
* 선택 영역 변환
* 다중 선택
* 검색과 바꾸기
* 문법 강조
* 마우스 조작과 드래그 정렬
* 단계 복제와 단계별 옵션 편집
* 파일 미리 불러오기
* 세션 복원과 선택적 충돌 복구
* 저장 체인 선택기
* 최근 변환 순위
* 퍼지 검색
* 단계별 결과 캐시
* 실행 중인 변환 내부의 협력 취소
* 실제 Output Viewport 행 수에 따른 `PageUp`·`PageDown` 이동량

기능을 추가할 때 입력 손실, 오래된 결과 복사, 터미널 복구, 큰 자료 렌더링 시험을 함께 추가한다.

## 14.6 사용자 스크립트

향후 사용자 요구가 확인되면 제한된 JavaScript `main(state)` 형태를 검토한다.

필수 선행 조건:

* 파일·네트워크·프로세스·환경 변수 접근 차단
* 메모리, 스택, 실행 시간, 출력 크기 제한
* 무한 루프 중단
* 허용 목록 기반 모듈 로더
* 새 실행 컨텍스트의 결정성
* 오류 스택의 입력 내용 비노출
* 스크립트 검색 경로와 파일 권한 정책

QuickJS 계열 런타임은 이 요구가 승인된 뒤에만 의존성으로 추가한다.

## 14.7 아키텍처 확장

* Cargo Workspace
* 공용 엔진의 독립 크레이트
* 별도 CLI·TUI 크레이트
* 편집기 어댑터
* 외부 플러그인 인터페이스
* Wasm 플러그인
* 비동기 런타임

두 번째 소비자, 독립 배포, 격리된 빌드, 실제 플러그인 요구가 생기기 전에는 추가하지 않는다.

## 14.8 시험과 성능

* 속성 기반 시험
* 퍼징
* 전용 스냅숏 시험 라이브러리
* 전체 변환 호환성 Golden 자료
* 구체적인 시작 시간·처리 시간·메모리 목표
* 대용량 스트리밍 변환
* 취소 가능한 실행기

첫 구현의 측정 자료나 재현 가능한 결함이 생길 때 추가한다.

## 14.9 플랫폼과 배포

* Windows 공식 지원
* macOS와 Linux용 미리 빌드한 실행 파일
* 체크섬과 서명
* GitHub Releases
* Homebrew
* Linux 배포판 패키지
* 코드 서명과 공증
* SBOM과 재현 가능한 빌드

v0.1은 소스 저장소에서 다음 방식으로만 설치한다.

```bash
cargo install --locked --path .
```

# 15. 주요 결정 기록

| 결정 | v0.1 결론 |
|---|---|
| 제품명 | Linux의 기존 `/usr/bin/beep` 충돌을 피하기 위해 `beep`에서 `toc`으로 변경 |
| 핵심 경험 | CLI 파이프라인과 TUI 비파괴 작업판 모두 포함 |
| 변환 수 | Base64 2개, URL 2개, JSON 2개로 제한 |
| 명령 형식 | `toc <transform-id>` 직접 실행, `run` 제거 |
| TUI 실행 | `toc tui`를 명시한 경우에만 실행 |
| 입력 | 파일 또는 파이프 중 하나, `--text` 제거 |
| 출력 | 표준 출력만 사용, 끝 줄바꿈 없음 |
| 체인 | `--then` 반복, 옵션 없음, 최대 32단계 |
| Base64 디코딩 | UTF-8 결과만 성공, 바이너리는 오류와 제한된 16진수 미리보기 |
| URL | RFC 3986 주소 구성요소 방식, 공백은 `%20`, `+` 유지 |
| JSON | 엄격 검증, 중복 키 거부, 토큰 원문 보존 |
| TUI | 빈 화면 시작, 저장·확정 없음, 입력과 Preview 분리 |
| 미리보기 | 200밀리초 지연, 작업 스레드 하나, 오래된 결과 폐기 |
| 실패 표시 | 이전·부분 결과 숨김, 복사 비활성화 |
| 플랫폼 | macOS와 Linux의 `bash`, `zsh`에서 CLI·TUI 검증 |
| 시험 자동화 | 로컬 시험만 수행하고 CI 설정은 제외 |
| 표시 언어 | CLI·TUI는 영어, 프로젝트 문서는 한국어 |
| 라이선스 | MIT 또는 Apache-2.0 |
| 구조 | 단일 Cargo 패키지와 정적 변환 등록 목록 |
| Rust | 최신 안정판 고정, 현재 `1.97.1`, 별도 MSRV 약속 없음 |
| 배포 | v0.1은 소스 설치만 제공 |
| Boop | 참고 모델일 뿐 호환성이나 진행 방향에 영향 없음 |
| v1.0 | v0.1 사용 결과를 확인한 뒤 별도 정의 |
