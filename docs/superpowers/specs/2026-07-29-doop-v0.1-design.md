# doop v0.1 구현 설계

* **작성일:** 2026-07-29
* **상태:** 사용자 승인
* **기준 문서:** `docs/prd/init-prd.md` 2.0
* **제품 UI 언어:** 영어
* **프로젝트 문서 언어:** 한국어
* **라이선스:** MIT 또는 Apache-2.0

---

# 1. 목적과 범위

이 문서는 승인된 PRD를 구현 가능한 내부 구조로 구체화한다. v0.1은 하나의 `doop` 실행 파일에서 다음 두 사용 방식을 제공한다.

1. 파일과 표준 입력을 처리하는 CLI
2. 비파괴 변환 작업판을 제공하는 TUI

두 방식은 같은 변환 등록 목록과 파이프라인을 사용한다. 구현 범위는 다음 여섯 변환으로 제한한다.

* `base64-encode`
* `base64-decode`
* `url-encode`
* `url-decode`
* `format-json`
* `minify-json`

저장 체인, 사용자 스크립트, 변환 옵션, 배포 패키지, CI 서비스는 구현하지 않는다.

# 2. 검토한 접근법

## 2.1 선택: 단일 패키지의 라이브러리와 실행 파일

`src/lib.rs`에 변환, 파이프라인, TUI 상태를 두고 `src/main.rs`는 운영체제 입출력과 종료 코드만 처리한다.

장점:

* CLI와 TUI가 공용 로직을 직접 재사용한다.
* 변환과 상태를 실행 파일을 띄우지 않고 단위 시험할 수 있다.
* Cargo Workspace 없이도 모듈 경계를 유지한다.
* 단일 실행 파일이라는 제품 요구와 일치한다.

## 2.2 제외: 실행 파일 모듈만 사용

파일 수는 적지만 공용 로직의 시험과 재사용이 불편하고 `main.rs` 중심 결합이 커질 수 있어 제외한다.

## 2.3 제외: Cargo Workspace

핵심 엔진과 프런트엔드를 강하게 격리할 수 있지만 여섯 변환과 단일 실행 파일에는 빌드 설정과 공개 경계가 과도해 제외한다.


`tui.rs`는 상태, 이벤트, 렌더링, 작업 스레드를 먼저 한 파일에 둔다. 실제로 읽기 어려울 정도로 커질 때만 `tui/` 하위 모듈로 나눈다.

## 3.1 모듈 책임

| 모듈 | 책임 | 의존 대상 |
|---|---|---|
| `main.rs` | 명령 실행, 표준 입출력, TTY 판정, 종료 코드 | `cli`, `pipeline`, `tui`, `error` |
| `cli.rs` | Clap 명령 생성, 입력원 조합 검증 | 변환 등록 목록 |
| `error.rs` | 내부 오류 자료형과 안전한 사용자 메시지 | 표준 라이브러리 |
| `pipeline.rs` | 단계 검증, 순차 실행, 단계별 출력 한도 | 변환 등록 목록 |
| `transforms` | 여섯 변환과 등록 목록 | `base64`, `serde_json` |
| `tui.rs` | TUI 상태, 이벤트, 렌더링, 작업 스레드, 클립보드 효과 | `pipeline`, Ratatui 계열 |

운영체제 작업은 가장 바깥 계층에서만 수행한다. 변환과 파이프라인은 파일, 터미널, 클립보드를 알지 못한다.

# 4. 변환 등록과 파이프라인

## 4.1 변환 정의

trait나 자동 등록 매크로를 만들지 않는다. 변환은 함수 포인터를 가진 정적 정의로 표현한다.

```rust
type TransformFn =
    fn(input: &[u8], output_limit: usize) -> Result<Vec<u8>, TransformError>;

struct TransformDefinition {
    id: &'static str,
    display_name: &'static str,
    description: &'static str,
    accepts_binary: bool,
    apply: TransformFn,
}
```

등록 목록은 정확히 여섯 항목을 가진 정적 배열이다. 식별자 조회는 여섯 항목의 선형 탐색으로 충분하다.

이 목록은 다음 세 위치의 단일 진실 공급원이다.

* CLI 변환 하위 명령
* TUI 변환 선택 목록
* 파이프라인 식별자 조회

## 4.2 단계

```rust
struct TransformStep {
    definition: &'static TransformDefinition,
    enabled: bool,
}
```

CLI에서 만든 단계는 모두 활성 상태다. TUI만 활성 상태를 전환한다.

## 4.3 파이프라인 실행

파이프라인 함수는 입력 소유권을 받고 최종 결과 소유권을 반환한다.

```rust
fn execute(
    input: Vec<u8>,
    steps: &[TransformStep],
    output_limit: usize,
) -> Result<Vec<u8>, PipelineError>
```

실행 규칙:

1. 단계 수가 32개 이하인지 확인한다.
2. 비활성 단계를 건너뛴다.
3. 현재 결과를 다음 변환에 전달한다.
4. 변환이 제한된 출력 버퍼를 사용하도록 출력 한도를 전달한다.
5. 실패하면 단계 번호와 변환 식별자를 원인 오류에 결합한다.
6. 모든 단계가 성공하면 최종 `Vec<u8>`만 반환한다.

CLI는 단계별 출력 한도로 256 MiB를 전달하고 TUI는 64 MiB를 전달한다.
단계 수 한도는 두 방식 모두 32개다.

중간 캐시, 병렬 단계 실행, 스트리밍 경로는 만들지 않는다.

## 4.4 제한된 출력 생성

출력을 모두 만든 뒤 크기만 검사하면 JSON 들여쓰기 같은 변환이 한도를 넘어 메모리를 할당할 수 있다. 각 변환은 다음 방식으로 한도 전에 실패한다.

* Base64 인코딩은 계산된 결과 길이를 먼저 검사한다.
* URL 인코딩은 `checked_add`로 필요한 길이를 계산한다.
* 디코딩은 결과가 입력보다 커지지 않는 성질을 이용하되 최종 길이를 확인한다.
* JSON 포맷은 쓰기 전에 남은 용량을 확인하는 작은 제한 버퍼를 사용한다.

제한 버퍼는 변환 모듈 내부에서만 사용하는 단순 `Vec<u8>` 래퍼다. 공개 추상화로 만들지 않는다.

# 5. CLI 설계와 자료 흐름

## 5.1 명령 생성

Clap builder API로 루트 명령을 만든다.

1. `tui` 예약 명령을 추가한다.
2. 등록 목록을 순회해 변환별 명령을 추가한다.
3. 각 변환 명령에 공통 `--input`과 반복 가능한 `--then`을 추가한다.
4. `--then`의 값도 등록 목록의 식별자로 제한한다.

이 방식은 `doop format-json --help`를 지원하면서 변환 식별자를 별도 CLI 열거형에 중복 선언하지 않는다.

루트 `--list`는 등록 순서대로 식별자, 표시 이름, 한 줄 설명을 출력한다.

## 5.2 입력

입력원 판정은 `std::io::IsTerminal`을 사용한다.

* `--input`과 파이프 표준 입력이 함께 존재하면 사용법 오류다.
* 둘 다 없으면 표준 입력을 기다리지 않고 사용법 오류다.
* 파일과 표준 입력은 `최대 크기 + 1바이트`까지만 읽는다.
* 추가 1바이트가 있으면 전체 자료를 더 읽지 않고 입력 한도 오류를 반환한다.

CLI 입력 한도는 64 MiB다.

## 5.3 실행과 출력

```text
인자 해석
  → 입력원 검증
  → 제한된 입력 읽기
  → 단계 해석
  → 공용 파이프라인
  → 실제 터미널 안전성 검사
  → write_all
```

원자성을 위해 최종 결과 전체가 성공할 때까지 표준 출력에 쓰지 않는다.

표준 출력 처리:

* TTY이고 위험한 제어 문자가 있으면 출력하지 않는다.
* 파이프나 파일이면 원본 결과를 그대로 쓴다.
* `BrokenPipe`는 조용히 성공 처리한다.
* 그 밖의 쓰기 실패는 코드 `5`다.

## 5.4 기본 명령과 언어

인자 없는 `doop`, 도움말, 목록, 오류는 영어로 출력한다. 프로젝트의 PRD와 설계 문서는 한국어로 유지한다. v0.1에는 지역화 계층을 만들지 않는다.

# 6. 변환 세부 설계

## 6.1 Base64

`base64` 라이브러리의 표준 엔진을 사용하되 설정을 명시한다.

인코딩:

* 표준 문자표
* 정규 `=` 패딩
* 계산한 결과 길이를 사전 검증

디코딩:

1. ASCII 공백, 탭, CR, LF만 제거한다.
2. 표준 문자표와 정규 패딩을 강제한다.
3. 사용되지 않는 마지막 비트를 거부한다.
4. 결과가 유효한 UTF-8인지 검사한다.
5. 비 UTF-8이면 최대 64바이트 16진수 미리보기를 오류 자료에 저장한다.

## 6.2 URL

인코딩은 별도 의존성 없이 바이트를 순회한다.

* RFC 3986 비예약 ASCII는 그대로 쓴다.
* 나머지 UTF-8 바이트는 대문자 `%HH`로 쓴다.
* 필요한 출력 크기를 먼저 계산한다.

디코딩은 `%` 뒤의 정확히 두 16진수를 읽는다. `+`는 특별 처리하지 않는다. 결과는 유효한 UTF-8이어야 한다.

## 6.3 JSON 검증

JSON은 원문 보존과 의미 검증을 분리한다.

### 의미 검증

`serde_json`의 임의 정밀도 숫자 기능을 활성화한다. 사용자 정의 방문자가 다음을 수행한다.

* 객체마다 `HashSet<String>`으로 디코딩된 키를 추적
* `"a"`와 `"\u0061"`을 같은 키로 판정
* 모든 배열과 객체의 값을 끝까지 방문
* 문법 오류의 줄과 열 보존
* 입력 끝 뒤의 추가 토큰 거부

오류 메시지에는 중복된 키 본문을 포함하지 않는다.

### 토큰 스캔과 출력

작은 상태 기계가 문자열 내부, 이스케이프, 구조 문자를 구분한다.

* 최상위 객체나 배열을 깊이 1로 계산
* 128단계를 넘으면 즉시 실패
* 문자열과 숫자 토큰을 원문 그대로 복사
* `format-json`은 구조 공백만 2칸 들여쓰기와 LF로 교체
* `minify-json`은 문자열 밖 공백만 제거
* 마지막 줄바꿈은 추가하지 않음

파싱한 값을 다시 직렬화하지 않는다.

# 7. TUI 설계와 자료 흐름

## 7.1 실행 경계

`main.rs`는 터미널을 초기화하기 전에 TUI 진입 조건을 검사한다.

* 정확히 `doop tui`만 허용하며 뒤따르는 명령이나 옵션은 코드 `2`로 거부한다.
* 표준 입력과 표준 출력이 모두 터미널이 아니면 원인을 표준 오류에 기록하고 코드 `1`로 종료한다.
* Input과 Chain은 항상 빈 상태로 만들고 파일, 표준 입력, 이전 상태를 불러오지 않는다.
* Input은 UTF-8 바이트 기준 16 MiB를 넘기는 편집이나 붙여넣기를 반영하지 않고 상태 메시지를 표시한다.
* Chain은 32단계에서 추가 동작을 거부한다.
* 미리보기 작업은 공용 파이프라인에 단계별 출력 한도 64 MiB를 전달한다.

## 7.2 상태

TUI 상태는 다음 자료를 소유한다.

* `tui-textarea-2` 입력 편집기
* 현재 포커스
* 변환 단계 목록과 선택 위치
* 변환 선택 창의 검색 문자열과 선택 위치
* 미리보기 상태
* 현재 세대 번호
* 지연 실행 마감 시각
* 종료 및 위험한 클립보드 확인 상태
* 상태 표시줄 메시지

미리보기 상태:

```text
Idle
Debouncing
Running { generation }
Ready { generation, document }
Error { generation, error }
```

`PreviewDocument`는 원본 `Arc<str>`과 줄 시작 오프셋만 보관한다. 렌더러는 현재 보이는 줄과 열만 안전하게 이스케이프해 큰 결과 전체를 매 프레임 복사하지 않는다.

## 7.3 상태 전이와 효과

상태는 이벤트를 받아 자신을 변경하고 운영체제 작업을 나타내는 효과를 반환한다.

```text
CopyToClipboard
SubmitPreviewJob
Quit
```

클립보드 trait나 편집기 adapter는 만들지 않는다. 이벤트 루프가 효과를 실행하고 성공·실패 결과를 다시 상태 이벤트로 전달한다.

시간 의존 전이는 현재 `Instant`를 인자로 받는다. 시험에서는 실제 대기 없이 원하는 시각을 전달한다.

## 7.4 최신 작업 한 칸

작업 스레드에는 `Mutex<Option<Job>>`와 `Condvar`를 사용한다.

1. Input 또는 Chain 변경 시 세대를 증가시킨다.
2. 200밀리초 뒤 입력과 활성 단계를 스냅숏으로 만든다.
3. 대기 중 작업이 있으면 최신 작업으로 덮어쓴다.
4. 작업 스레드는 한 작업을 실행해 표준 채널로 결과를 이동한다.
5. UI는 현재 세대와 같은 결과만 반영한다.

실행 중인 작업은 중단하지 않는다. UI 스레드는 작업 제출이나 결과 대기로 정지하지 않는다.

## 7.5 표시 안전성

한 공용 함수가 탭, LF, CR을 제외한 C0·C1 제어 문자를 위험 문자로 판정한다.

* TUI 붙여넣기에서는 CRLF와 CR을 LF로 바꾼다.
* 위험한 입력 문자는 `\xNN` 형태의 표시 가능한 문자열로 치환한다.
* Preview의 위험 문자는 원본을 유지하고 표시할 때만 이스케이프한다.
* 위험한 원본 결과를 복사할 때 확인 창을 표시한다.

색상은 상태의 유일한 표지가 아니다. `NO_COLOR`가 있으면 장식 색상을 사용하지 않는다.

## 7.6 터미널 수명

RAII 보호 객체가 다음 기능을 관리한다.

1. raw mode
2. 대체 화면
3. bracketed paste
4. 커서 표시 상태

초기화의 역순으로 복구하며 일부 초기화만 성공한 경우에도 성공한 항목만 되돌린다.

* `Ctrl+Q`: 입력이 있으면 폐기 확인 뒤 정상 종료
* `Ctrl+C`: 확인을 생략하고 코드 `130`으로 강제 종료
* 오류와 패닉: 보호 객체의 `Drop`과 외부 `catch_unwind` 경계로 복구

## 7.7 클립보드

`arboard`는 Preview에서 복사를 요청한 시점에만 초기화한다.

* 성공하면 짧은 상태 메시지를 표시한다.
* 실패하면 오류를 표시하고 Input과 Preview를 유지한다.
* Linux에서 애플리케이션 종료 후 클립보드 유지용 프로세스를 만들지 않는다.

---

# 8. 오류와 종료 코드

## 8.1 내부 오류

```text
InputError
TransformError
PipelineError { step, transform_id, source }
TuiError
```

내부 오류와 사용자 출력은 분리한다.

* 동적 문자열의 제어 문자를 이스케이프한다.
* 입력 원문, JSON 키 본문, 전체 결과를 출력하지 않는다.
* 줄·열·바이트 위치는 확인 가능한 경우에만 포함한다.
* 파이프라인은 실패 단계와 변환 식별자를 보존한다.
* Base64와 URL의 비 UTF-8 결과에만 제한된 16진수 미리보기를 허용한다.

## 8.2 종료 코드 변환

| 오류 | 코드 |
|---|---:|
| 성공, 도움말, 목록 | `0` |
| TUI 또는 일반 실행 환경 | `1` |
| 명령, 옵션, 입력원 조합 | `2` |
| 입력 읽기 또는 입력 한도 | `3` |
| 변환 또는 단계 출력 한도 | `4` |
| 표준 출력 쓰기 | `5` |
| 사용자 인터럽트 | `130` |

TUI 화면 안에서 복구 가능한 클립보드 오류는 프로세스를 종료하지 않는다.

# 9. 시험 설계

모든 시험은 로컬에서 실행한다. GitHub Actions와 다른 CI 설정은 만들지 않는다.

## 9.1 단위 시험

각 모듈 가까이에 작은 시험을 둔다.

* 등록 목록 개수, 식별자 중복, `tui` 충돌
* 여섯 변환의 정상·오류·경계 입력
* Base64·URL의 UTF-8 제한과 64바이트 미리보기
* JSON 원문 보존, 중복 키, 128단계 깊이
* 단계 수, 출력 한도, 실패 단계
* 위험한 제어 문자 판정과 안전한 표시
* TUI 상태 전이와 세대 판정

## 9.2 CLI 통합 시험

표준 `std::process::Command`로 빌드된 `doop`을 실행한다.

* 파일과 파이프 입력
* 입력원 충돌과 입력 없음
* 도움말, 버전, 목록, 변환별 도움말
* 반복 `--then`
* stdout, stderr, 종료 코드
* 끝 줄바꿈 부재
* 끊어진 파이프 처리

임시 파일은 충돌하지 않는 이름으로 만들고 시험 종료 시 정리한다. 별도 명령 시험 프레임워크는 추가하지 않는다.

## 9.3 TUI 시험

Ratatui `TestBackend`와 순수 상태 전이를 사용한다.

* 120열 이상 세 영역
* 120열 미만 탭
* 최소 화면 안내
* 단계 추가·삭제·이동·활성화
* 변환 선택 필터
* 지연 미리보기와 오래된 결과 폐기
* 오류 시 이전 결과와 복사 제거
* 종료 및 위험한 복사 확인
* `NO_COLOR`

실제 시스템 클립보드는 자동 시험하지 않는다. 복사 효과와 성공·실패 이벤트를 시험한다.

## 9.4 셸과 운영체제 확인

동일한 `tests/shell-smoke.sh`를 다음처럼 실행한다.

```bash
bash tests/shell-smoke.sh
zsh tests/shell-smoke.sh
```

스크립트는 파일·파이프·체인 동작을 확인한다. 운영체제별 `script` 명령으로 가상 터미널을 할당해 TUI 시작, 강제 종료, 터미널 복구를 짧게 확인한다.

현재 macOS에서 전체 시험을 실행한다. Linux 환경이 없으면 구현 결과에 “Linux 미검증”을 명시하고, Linux가 준비되면 같은 명령으로 공식 지원 검증을 완료한다.

소스 설치는 저장소 안의 시험용 설치 루트에서 검증하고 설치된 `doop --version`을 실행한다. 사용자의 기존 Cargo 실행 파일은 덮어쓰지 않는다.

## 9.5 필수 로컬 명령

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
cargo install --locked --path . --root target/install-check
target/install-check/bin/doop --version
bash tests/shell-smoke.sh
zsh tests/shell-smoke.sh
```

속성 시험, 퍼징, 코드 커버리지, 전용 스냅숏 라이브러리는 v0.1에 추가하지 않는다.

# 10. 의존성, 도구 체인, 라이선스

## 10.1 런타임 의존성

* `clap`
* `ratatui`
* `crossterm`
* `tui-textarea-2`
* `arboard`
* `base64`
* `serde`
* `serde_json`

구현 시작 시 Rust `1.97.1`에서 호환되는 최신 안정 버전을 선택하고 `Cargo.lock`으로 고정한다. 사용하지 않는 선택 기능은 비활성화한다.

## 10.2 도구 체인

* Rust 2024 Edition
* `rust-toolchain.toml`에 `1.97.1` 고정
* 별도 최소 지원 Rust 버전 약속 없음

## 10.3 라이선스

저장소 루트에 MIT와 Apache-2.0 전문을 각각 둔다. `Cargo.toml`에는 다음 SPDX 표현식을 사용한다.

```toml
license = "MIT OR Apache-2.0"
```
