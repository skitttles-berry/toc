# doop v0.2 16진수 변환 설계

* **작성일:** 2026-07-30
* **상태:** 사용자 승인
* **기준 문서:** `docs/prd/v0.2-prd.md`, `docs/prd/init-prd.md` 2.0
* **제품 UI 언어:** 영어
* **프로젝트 문서 언어:** 한국어

---

# 1. 범위와 원칙

v0.2는 v0.1의 단일 Cargo 패키지, 정적 변환 레지스트리, 공용 파이프라인을 유지한 채 `hex-encode`와 `hex-decode`를 추가한다. 사용자 승인된 설계 문서이며 구현 계획이나 코드가 아니다.

기존 CLI 입력·출력, 종료 코드, 터미널 안전성, TUI 비파괴 미리보기, 최대 32단계, CLI 64 MiB 입력·256 MiB 단계 출력, TUI 1 MiB 입력·64 MiB 단계 출력은 v0.1 문서를 그대로 따른다.

# 2. 모듈과 등록

예정 모듈은 `src/transforms/hex.rs`다. `src/transforms/mod.rs`는 이 모듈을 등록 목록에 직접 추가한다. trait, 팩터리, 자동 등록 매크로, 별도 크레이트, 새 16진수 의존성은 만들지 않는다.

등록 목록의 공개 식별자 집합은 다음 정확히 8개 항목이다. 각 식별자는 한 번만 등록하며 `tui`와 충돌하지 않는다.

| ID | 표시 이름 | 이진 입력 |
|---|---|---|
| `base64-encode` | `Base64 Encode` | 예 |
| `base64-decode` | `Base64 Decode` | 아니오 |
| `url-encode` | `URL Encode` | 아니오 |
| `url-decode` | `URL Decode` | 아니오 |
| `format-json` | `JSON Prettify` | 아니오 |
| `minify-json` | `JSON Minify` | 아니오 |
| `hex-encode` | `Hex Encode` | 예 |
| `hex-decode` | `Hex Decode` | 아니오 |

이 목록은 CLI 하위 명령과 도움말, `doop --list`, TUI 선택 창, 파이프라인 조회의 단일 진실 공급원이다. CLI와 TUI에 별도 목록이나 별도 변환 구현을 두지 않는다. 표의 표시 순서와 `doop --list`의 표시 순서는 v0.2의 공개 호환성 규약이 아니다.

# 3. 실행 규칙

## 3.1 `hex-encode`

`hex-encode`는 입력 바이트 하나를 소문자 ASCII 16진수 두 문자로 변환한다. `00`, `0a`, `ff` 같은 출력만 만들고 접두사, 구분자, 공백, 그룹, 끝 줄바꿈을 추가하지 않는다. 입력이 빈 경우에도 같은 규칙으로 빈 결과를 반환한다. CLI는 표준 입력과 파일의 임의 바이트를 지원하지만, TUI Input은 v0.1의 UTF-8 문자열 범위를 유지하므로 임의의 비 UTF-8 바이트를 직접 입력하지 않는다.

필요 출력 크기는 `input.len().checked_mul(2)`로 계산한다. 오버플로 또는 출력 한도 초과면 `OutputTooLarge`로 실패하고 결과 버퍼는 만들지 않는다. 한도 안이면 정확한 크기로 한 번 할당해 상위·하위 반쪽 문자를 기록한다.

## 3.2 `hex-decode`

`hex-decode`는 텍스트 변환이다. 공용 파이프라인이 먼저 UTF-8 입력 조건을 확인한다. 그 뒤 원본 입력 바이트를 왼쪽부터 검사한다.

1. `0x20`, `0x09`, `0x0d`, `0x0a`는 건너뛴다.
2. ASCII 16진수는 대소문자 구별 없이 숫자 하나로 센다.
3. 나머지 바이트는 즉시 `InvalidHex` 오류로 끝내고 현재 원본 바이트 오프셋을 보존한다.
4. 검사가 끝난 뒤 숫자 수가 홀수면 `OddHexDigitCount` 오류로 끝낸다.
5. 숫자 수의 절반이 출력 한도를 넘지 않는지 확인한 뒤에만 정확한 출력 크기를 할당한다.
6. 두 번째 순회에서 인접한 두 숫자를 한 바이트로 만든다.
7. 결과를 UTF-8로 검증하고 성공한 바이트만 반환한다.

첫 순회는 공백 없는 임시 문자열을 만들지 않는다. 따라서 공백이 많은 입력도 결과 크기만큼의 버퍼 외에 입력 길이 비례 추가 버퍼를 요구하지 않는다.

ASCII 이외의 공백은 무시하지 않는다. 유효 UTF-8인 경우 해당 문자 첫 바이트가 `InvalidHex` 위치다. UTF-8이 아닌 입력은 스캐너보다 앞선 기존 `InvalidUtf8Input` 경로를 따른다.

# 4. 오류 모형과 표시

기존 `TransformError`에 다음 두 변형을 추가한다.

```text
InvalidHex { position: usize }
OddHexDigitCount { digits: usize }
```

이 두 값은 변환 오류의 구체적 원인을 보존한다. 사용자 표시 문구는 영어로 다음처럼 고정한다.

| 조건 | 표시 문구 |
|---|---|
| 허용되지 않는 바이트 | `invalid hex character at byte {position}` |
| 홀수 숫자 수 | `hex input has an odd number of digits: {digits}` |
| 비 UTF-8 결과 | 기존 `decoded bytes are not UTF-8 ...` |
| 출력 한도 초과 | 기존 `transform output exceeds {limit} bytes` |

`0x`는 `x`가 원본 오프셋 1이므로 첫 행의 오류다. `0`을 접두사로 해석하거나 홀수 숫자 수 오류로 바꾸지 않는다. 콜론과 쉼표도 현재 원본 오프셋에서 `InvalidHex`다. 홀수 숫자 수는 허용 문자와 허용 ASCII 공백만 끝까지 확인한 경우에만 보고하며, 공백을 제외한 실제 숫자 수를 포함한다.

`InvalidUtf8Output`은 수정하지 않는다. `hex-decode`도 Base64 및 URL 디코더와 동일하게 처음 64바이트의 소문자 16진수 미리보기와 전체 바이트 수를 사용한다. 64바이트 초과 시 기존 생략 표시를 유지하며, 원시 결과나 입력 전문을 오류에 넣지 않는다.

파이프라인은 기존 `PipelineError::Step`으로 1부터 시작하는 단계 번호와 `hex-encode` 또는 `hex-decode` ID를 결합한다. 모든 16진수 형식 오류와 출력 한도 오류는 기존 코드 `4`로 매핑된다.

# 5. 파이프라인과 자원 경계

`hex-encode`는 이진 입력을 허용하므로 다른 이진 입력 허용 변환과 동일하게 파이프라인의 UTF-8 사전 검증을 건너뛴다. `hex-decode`는 텍스트 입력만 받아 사전 UTF-8 검증을 받으며, 성공 결과도 UTF-8로 제한한다. 이로써 TUI의 문자열 미리보기와 기존 성공 결과 불변식을 유지한다.

모든 결과는 변환 함수의 `output_limit`을 사용한다. 인코딩의 길이 계산과 디코딩의 숫자 수 산술은 `checked_mul`, `checked_add` 및 한도 비교로 검사한다. 파이프라인의 기존 단계 후 한도 검사는 방어적 보조 검사로 남긴다. 한도보다 큰 `Vec::with_capacity` 호출이나 결과 전체를 만든 뒤의 사후 거부는 허용하지 않는다.

CLI는 공용 파이프라인의 성공 전에는 표준 출력에 쓰지 않으며, TUI는 같은 실행 함수의 성공 결과 또는 오류만 미리보기에 반영한다. 따라서 CLI와 TUI에 표현 가능한 동일한 UTF-8 입력과 동일한 체인은 같은 결과 또는 오류를 낸다.

# 6. 시험 경계

구현 시 기존 모듈 가까이에 다음 최소 시험을 둔다.

* 레지스트리의 정확한 8개 공개 ID 집합, 중복 부재, `tui` 비충돌, 이름·설명 존재를 검증한다.
* `hex-encode`의 빈 입력, CLI의 임의 이진 바이트, 소문자 출력, 접두사·구분자·줄바꿈 부재를 검증한다. TUI는 UTF-8 입력 범위만 다룬다.
* `hex-decode`의 대소문자, ASCII space/tab/CR/LF 혼합, 빈 입력을 검증한다.
* `0x`의 오프셋 1, 콜론·쉼표의 원본 오프셋, 비 ASCII 공백의 첫 UTF-8 바이트 오프셋을 검증한다.
* 공백을 제외한 숫자 수가 홀수일 때 `OddHexDigitCount`와 정확한 `digits`를 검증한다.
* 출력 한도 경계와 계산 전 거부를 검증한다. 인코더는 두 배 확장, 디코더는 숫자 수의 절반을 기준으로 한다.
* 비 UTF-8 결과의 64바이트 미리보기, 64바이트 초과 생략, 전체 길이를 기존 디코더와 같은 방식으로 검증한다.
* `hex-encode`와 `hex-decode`의 체인, 실패 단계 번호와 ID, CLI 목록·도움말 및 TUI 선택이 같은 레지스트리를 사용하는 경계를 검증한다.

새 시험 프레임워크, 속성 시험, 퍼징, CLI/TUI 전용 레지스트리 모의 객체는 추가하지 않는다.

# 7. 보류한 확장

다음은 의도적으로 설계·구현하지 않는다.

* 대문자 인코딩, 사용자 선택 문자표
* `0x`, 콜론, 쉼표, 임의 구분자 및 그룹화 입력
* 줄 폭, 그룹 크기, 접두사, 끝 줄바꿈 옵션
* 유효하지 않은 UTF-8을 원시 이진 결과로 전달하거나 TUI에 표시하는 경로
* 스트리밍 디코더와 별도 16진수 라이브러리

이 요구가 필요해지면 기존 공개 입력 규약과 UTF-8 성공 결과 불변식에 미치는 영향을 별도 승인 문서에서 검토한다.
