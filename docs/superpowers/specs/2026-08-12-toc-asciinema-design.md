# toc asciinema 녹화 설계

## 목표

README에서 TUI의 대표 사용 흐름을 바로 확인할 수 있게 한다. 녹화는 실제 터미널
색상과 키 흐름을 유지하며 짧게 재생한다.

## 산출물

- `docs/asciinema/toc-tui.cast`: TUI 입력·변환 추가·실행·결과 확인 녹화
- `README.md`: asciinema.org의 TUI 녹화로 이동하는 SVG 미리보기 하나

원본 asciicast는 재녹화와 로컬 재생을 위해 저장소에 보관한다. 공개 페이지는 검색
목록에 노출되지 않는 `unlisted`로 업로드한다.

## TUI 시나리오

120×30 터미널에서 실제 `toc tui`를 열어 다음 흐름을 보여준다.

1. Input에 `hello` 입력
2. Picker에서 Base64 Encode와 SHA-256 추가
3. Pipeline의 선택 단계를 실행하고 최종 결과로 복귀
4. Output View를 전환해 Trace 확인 후 정상 종료

녹화는 실제 키 입력과 렌더링만 담고 설명용 오버레이나 별도 데모 코드는 추가하지
않는다. 셸에서 `$ toc tui`를 실행하는 장면은 유지한다. TUI가 셸로 돌아온 뒤에는
화면에 문자가 남지 않는 `Ctrl+D`로 녹화를 끝내며 `exit`를 입력하지 않는다.

녹화 세션은 `TERM=xterm-256color`를 사용하고 `NO_COLOR`를 해제한다. toc가 사용하는
터미널 기본색과 ANSI 기본색(시안·녹색·노란색·빨간색)을 asciicast에 그대로 기록한다.

## 안전성과 검증

- 키 입력 캡처 옵션은 사용하지 않고 통제된 예제 값만 입력한다.
- 현재 빌드한 release 실행 파일로 TUI 시나리오를 녹화한다.
- `asciinema play`로 원본을 재생하고 종료 상태, 120×30 크기, 주요 출력 문자열,
  ANSI 색상 코드를 확인한다.
- 원본 이벤트에 셸의 `exit` 출력이 없는지 확인한다.
- 업로드 후 녹화 페이지와 SVG 미리보기의 응답을 확인하고 README 링크를 검사한다.
- 코드 동작은 바꾸지 않으므로 기존 전체 시험 대신 release 빌드, 녹화 재생,
  `git diff --check`를 수행한다.

## 제외 범위

CLI 녹화, 음성, 자막, GIF 변환, 별도 녹화 자동화 스크립트, 자체 플레이어 호스팅은
추가하지 않는다. 먼저 만든 CLI 원본은 저장소와 README에서 제외하며, 계정에 연결하지
않은 임시 업로드는 자동 만료되도록 둔다.
