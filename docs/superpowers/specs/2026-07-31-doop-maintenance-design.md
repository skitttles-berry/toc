# doop 안정화·단순화 설계

* **작성일:** 2026-07-31
* **상태:** 사용자 승인·구현 대기
* **기준 문서:** `docs/prd/init-prd.md`, `docs/prd/v0.2-prd.md`
* **대상:** CLI, TUI, 로컬 시험과 프로젝트 문서
* **제품 UI 언어:** 영어
* **프로젝트 문서 언어:** 한국어

---

# 1. 목적

이 설계는 현재 doop의 공개 동작과 단일 Cargo 패키지 구조를 유지하면서 확인된 표시 결함, 불필요한 자원 사용, 작업자 종료 처리와 과거 문서 중복을 정리한다.

대규모 재작성이나 추측 기반 최적화는 하지 않는다. 확실한 결함과 낭비는 발생 지점에서 고치고, TUI 입력 처리와 UTF-8 검사는 릴리스 측정 결과가 기준을 넘을 때만 최적화한다.

# 2. 범위

## 2.1 포함

* 긴 단일 행을 화면 너비에 맞춰 표시하는 TUI Text View
* 작업자 결과 채널의 `Empty`와 `Disconnected` 구분
* 작업자 비정상 종료 시 안전한 TUI 종료와 터미널 복구
* CLI Pipeline 단계 수의 입력 읽기 전 검증
* 공백 없는 Base64 디코딩 입력의 중간 복사 제거
* macOS 실제 클립보드 Smoke의 백업·소유권 추적·복원 제거
* 최대 TUI 입력 편집과 최대 결과 UTF-8 판정의 릴리스 측정
* 완료된 구현 계획과 README의 과거 검증 전문 정리
* 관련 PRD, 승인 설계와 README 현행화

## 2.2 제외

* 공개 명령, 옵션, 변환 ID, 성공 결과, 오류 형식과 종료 코드 변경
* 작업자 자동 재시작과 작업자 관리자
* 방향키 이동 단위와 고정 10단위 `PageUp`·`PageDown` 변경
* 새 캐시·공통 프레임워크·비동기 런타임·외부 의존성
* 신규 변환, 파일 입출력, 검색, 부분 복사와 플러그인
* GitHub Actions와 원격 CI
* 측정 기준을 넘지 않은 성능 경로의 선제 최적화

이번에 구현하지 않는 제품 아이디어는 `docs/prd/init-prd.md`와 기존 TUI 설계의 후속 작업 대장에 계속 보관한다.

# 3. 변경 원칙

기존 모듈 경계를 유지하고 문제 발생 지점만 수정한다.

```text
src/cli.rs                 단계 수 조기 검증
src/transforms/base64.rs   조건부 공백 압축
src/tui.rs                 작업자 채널 종료 처리
src/tui/worker.rs          채널 수신 결과 보존
src/tui/views.rs           Text View 표시용 자동 줄바꿈
tests/shell-smoke.sh       복원 없는 실제 클립보드 검증
```

프로덕션 모듈, trait, 작업자 추상화와 설정 항목을 새로 만들지 않는다. Pipeline 내부의 기존 단계 수 검사는 CLI 이외 호출자를 보호하므로 유지한다.

# 4. TUI Text View

## 4.1 표시 규칙

Text View는 유효한 UTF-8 결과만 표시하고 원본 Artifact를 수정하지 않는다. 기존의 제어문자 escape, 그래핌 경계, Unicode 표시 폭과 4 KiB 렌더링 예산을 유지한다.

다음 그래핌의 표시 폭이 현재 화면 행의 남은 폭을 넘으면 다음과 같이 처리한다.

1. 현재 행에 이미 표시된 내용이 있으면 표시용 `LF`를 추가한다.
2. 화면 행을 하나 증가시키고 폭을 0으로 초기화한다.
3. 같은 그래핌을 새 행에서 다시 검사한다.
4. 새 행에 들어가면 그때 원본 바이트 위치를 소비한다.

화면 행이나 4 KiB 예산이 끝나면 아직 표시하지 않은 그래핌은 소비하지 않는다. `TextWindow.next_offset`은 마지막으로 완전히 표시한 그래핌 다음의 원본 바이트 위치를 가리킨다.

그래핌 하나의 표시 문자열 자체가 빈 행의 전체 너비보다 넓으면 기존의 전진 보장을 적용한다. 필요하면 표시 가능한 생략 기호를 사용하고 다음 UTF-8 경계로 이동하여 같은 위치에서 렌더링이 반복되지 않게 한다.

## 4.2 비변경 영역

* 원본 문자열과 클립보드 payload에는 표시용 줄바꿈을 넣지 않는다.
* 실제 `LF`와 `CRLF`의 기존 표시 규칙을 유지한다.
* 방향키는 기존처럼 그래핌 단위로 이동한다.
* `PageUp`과 `PageDown`은 기존처럼 10번 이동한다.
* Hex와 Trace View는 변경하지 않는다.

# 5. 작업자 종료 처리

`PreviewWorker::try_recv`는 `mpsc::Receiver::try_recv`의 의미를 잃지 않도록 다음 세 상태를 호출자에게 전달한다.

```text
Ok(result)           결과를 App에 반영
Err(Empty)           현재 이벤트 루프 계속
Err(Disconnected)    안전한 TUI 오류 반환
```

`Disconnected`는 작업자 스레드가 비정상 종료되어 새 결과를 만들 수 없는 상태다. 이벤트 루프는 `AppError::Tui("Preview worker stopped unexpectedly")`를 반환하고 더 이상 작업을 제출하거나 오래된 결과를 표시하지 않는다.

`tui::run`의 기존 단일 정리 경로가 raw mode, bracketed paste, 대체 화면, 커서와 패닉 훅을 복구한다. 자동 재시작, 작업 재전송과 입력 내용이 포함된 진단은 추가하지 않는다. 최종 공개 종료 코드는 기존 TUI 오류와 같은 1이다.

# 6. CLI 단계 수 조기 검증

`run_transform`은 첫 단계와 `--then` 단계의 합이 `MAX_STEPS`를 넘는지 `read_input` 전에 확인한다.

단계 수를 초과하면 기존 `PipelineError::TooManySteps { max: MAX_STEPS }`를 `AppError::Pipeline`으로 반환한다. 따라서 단계 초과와 입력 파일 오류 또는 표준 입력 오류가 동시에 있으면 단계 초과 오류가 우선한다.

Pipeline 실행 함수의 기존 검사는 제거하지 않는다. CLI 이외의 직접 호출과 향후 내부 호출도 같은 32단계 한도를 적용한다.

# 7. Base64 디코딩 메모리

Base64 디코더는 먼저 입력에 허용된 ASCII 공백인 스페이스, 탭, 캐리지 리턴 또는 줄바꿈이 있는지 검사한다.

* 공백이 없으면 원본 `&[u8]`를 직접 디코더에 전달한다.
* 공백이 있으면 기존처럼 해당 네 종류만 제거한 소유 버퍼를 만든다.

길이, 패딩, 정규형, 출력 한도와 UTF-8 정책은 변경하지 않는다. 디코딩 오류 위치는 압축 입력이 아니라 원본 입력의 바이트 위치로 계속 보고한다. 공백이 없는 최대 CLI 입력에서는 입력 크기만큼의 중간 버퍼를 만들지 않는다.

# 8. 성능 측정과 조건부 최적화

## 8.1 측정 대상

릴리스 전용 무시 시험으로 다음 두 경로를 측정한다.

* 1 MiB보다 1바이트 작고 정확히 65,536줄인 TUI 입력의 끝에서 선택 영역 없이 출력 가능한 ASCII 1바이트를 삽입하는 상태 처리 시간
* 미리 만든 64 MiB 유효 UTF-8 성공 바이트에서 `std::str::from_utf8`로 유효성을 판정하는 시간

각 측정은 준비와 대형 버퍼 생성을 측정 구간 밖에서 수행한다. 5회 준비 실행 뒤 30회 표본의 중앙값을 대표값으로 사용하고 중앙값, 최솟값, 최댓값과 반복 횟수를 출력한다. 시간 자체는 시험 합격 조건으로 사용하지 않는다. 느린 장비라는 이유만으로 전체 시험이 실패해서는 안 된다.

## 8.2 적용 기준

현재 구현 장비의 릴리스 측정 중앙값이 16 ms를 초과할 때만 해당 경로를 최적화한다.

입력 편집이 기준을 넘으면 App이 전체 입력 바이트 수와 줄 수를 보관하고, 성공한 문서 변경마다 갱신한다. 선택 영역 교체처럼 선택 크기가 필요한 경우에만 선택 범위를 계산한다. 거부된 입력, 커서 이동과 선택 이동은 보관한 통계를 변경하지 않는다.

UTF-8 판정이 기준을 넘으면 작업자가 성공 결과의 UTF-8 여부를 계산해 `PreviewResult`에 함께 전달한다. UI 스레드는 검증된 불리언으로 `Artifact`를 만들고 화면 표시 때는 기존의 제한된 UTF-8 조각 검증을 유지한다. 클립보드 복사는 기존처럼 원본을 보존하며 손실 변환을 하지 않는다.

기준을 넘지 않은 경로는 현재 구조를 유지한다. 측정값과 최적화 적용 여부는 README의 최신 로컬 검증 요약에 기록한다.

2026-07-31 macOS 26.5.2(25F84), Darwin 25.5.0 arm64, Rust·Cargo 1.97.1에서 `cargo test --release max_input_edit_release_measurement -- --ignored --nocapture`와 `cargo test --release utf8_validation_release_measurement -- --ignored --nocapture`를 실행했다. 5회 준비 실행 뒤 30표본 중앙값은 각각 2.82475 ms와 2.262584 ms였다. 두 경로 모두 16 ms 이하이므로 조건부 최적화를 적용하지 않고 현재 구현을 유지한다. 시간 숫자는 시험 합격 기준이 아니다.

# 9. 클립보드 Smoke 단순화

제품의 클립보드 복사 동작은 변경하지 않는다. 변경 대상은 `DOOP_SMOKE_CLIPBOARD_MODE=macos` 시험뿐이다.

제거 항목은 다음과 같다.

* 시험 전 클립보드 형식 사전 검사
* 원문 백업과 임시 백업 파일
* `NSPasteboard.changeCount` 추적
* 시험 중 클립보드 소유권 판정
* 성공·실패·신호 종료 시 원문 복원과 복원 검증
* 복원이 불가능할 때 임시 파일을 보존하는 경로

macOS 경로는 TUI에서 바이너리 결과를 복사한 뒤 `pbpaste`로 소문자 `ff`가 읽히는지만 확인한다. 시험 종료 뒤 클립보드에 `ff`가 남아도 성공이다. Linux의 미지원, X11과 Wayland 복사 검증은 유지한다.

터미널 복구는 클립보드 복원과 별개다. 정상 종료, 강제 인터럽트와 오류 경로의 터미널 모드 복구 시험은 그대로 유지한다.

## 10.2 삭제·축소

구현이 끝난 다음 과거 구현 계획 다섯 개를 작업 트리에서 삭제한다.

```text
docs/superpowers/plans/2026-07-29-doop-v0.1.md
docs/superpowers/plans/2026-07-29-doop-v0.2-hex.md
docs/superpowers/plans/2026-07-30-doop-full-audit-refactor.md

```

삭제한 계획은 Git 이력으로 보존한다. 새 구현 계획은 현재 작업이 끝날 때까지 유지한다.

README에서는 반복된 과거 커밋 해시, 환경별 실행 전문과 중복 결과를 제거한다. 사용 명령, 로컬 검증 명령, 지원 플랫폼, 아직 검증하지 못한 환경과 최신 검증 결과 한 벌만 남긴다.

현재 PRD와 TUI 설계에서 macOS 클립보드 복원을 필수로 규정한 문구는 복사 결과 확인만 요구하도록 바꾼다. 과거 사실을 설명할 필요가 없는 현행 문서에서는 `changeCount`, 백업과 복원 설명을 제거한다.

# 11. 시험 전략

기능 변경은 실패 시험을 먼저 확인하고 최소 코드로 통과시킨다.

* Text View: ASCII 장문, 넓은 Unicode 그래핌, 결합 문자, 실제 줄바꿈, 위험 제어문자, 행·열 경계와 4 KiB 예산
* 작업자: 정상 결과, `Empty`, 작업자 패닉 뒤 `Disconnected`, Drop과 취소
* CLI: 32단계 경계와 33단계에서 입력을 읽지 않는 Reader
* Base64: 공백 유무, 원본 기준 오류 위치, 패딩, 출력 한도와 비 UTF-8 결과
* 셸: Bash·Zsh 기본 TUI, 터미널 복구, macOS 복사값, Linux 미지원·X11·가능한 Wayland
* 문서: 제거된 복원 규약, 완료 계획 참조와 중복 검증 기록 검색

필수 로컬 검증은 다음 범주를 포함한다.

```text
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
릴리스 성능 측정
RUSTDOCFLAGS=-D warnings cargo doc --no-deps --all-features
cargo package --locked
오프라인 잠금 설치와 버전 확인
Bash·Zsh shell smoke
사용 가능한 운영체제별 실제 클립보드 smoke
ccc index
```

# 12. 완료 기준

다음을 모두 만족하면 구현을 완료한 것으로 본다.

* 기존 공개 CLI 명령, 변환 ID, 성공 결과, 오류 형식과 종료 코드가 유지된다.
* 긴 Text 결과가 원본을 바꾸지 않고 화면의 여러 행을 사용한다.
* 작업자 채널 종료가 무한 `Running` 상태를 만들지 않는다.
* 작업자 종료 뒤 TUI가 오류 코드 1로 끝나고 터미널이 복구된다.
* 33단계 이상인 CLI 요청은 입력을 읽기 전에 실패한다.
* 공백 없는 Base64 입력은 전체 크기의 압축 복사본을 만들지 않는다.
* macOS Smoke는 복사값만 확인하고 클립보드를 복원하지 않는다.
* 성능 측정 결과와 조건부 최적화 적용 여부가 기록된다.
* 완료된 과거 계획과 중복 검증 전문이 현재 문서에서 정리된다.
