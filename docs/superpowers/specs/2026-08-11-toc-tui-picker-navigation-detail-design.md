# toc Add Transform 순환 이동·상세 구분 설계

**작성일:** 2026-08-11
**상태:** 사용자 승인
**대상:** `toc tui` Add Transform Modal

## 1. 목적

Add Transform 목록의 끝에서 선택이 멈추지 않고 반대쪽 끝으로 이어지게 한다. 목록 아래
상세 영역에는 선택한 변환 이름을 명시해 목록 항목과 설명의 관계를 바로 알 수 있게 한다.

기존 검색, 클릭, 추가, 취소, Backspace 검색어 편집과 반응형 Modal 구조는 유지한다.

## 2. 확정 동작

### 2.1 순환 선택

- 마지막 검색 결과에서 `↓`를 누르면 첫 결과를 선택한다.
- 첫 검색 결과에서 `↑`를 누르면 마지막 결과를 선택한다.
- 목록 위의 마우스 휠도 같은 규칙을 사용한다.
- 검색 결과가 없으면 선택값 `0`을 유지하고 화면을 다시 그리지 않는다.
- 검색 결과가 하나면 선택이 바뀌지 않으며 화면을 다시 그리지 않는다.
- 검색어가 바뀌면 기존처럼 첫 결과를 선택한다.

키보드와 마우스 휠은 현재처럼 `handle_modal_key`의 `Up`·`Down` 처리를 공유한다. 별도
키맵이나 목록 탐색 계층은 만들지 않는다. 선택값이 바뀌면 기존 렌더링의 `start` 계산이
새 위치를 화면 안에 표시한다.

### 2.2 상세 영역 구분

일반 화면에서는 기존 목록·상세 구분선에 선택한 표시 이름을 넣는다.

```text
> Base64 Encode
  Base64 Decode
──── Base64 Encode ─────────────────
ID        base64-encode
ABOUT     Encode bytes using padded RFC 4648 Base64
INPUT     Bytes accepted
```

별도 행을 추가하지 않으므로 현재 상세 필드 수와 목록 높이는 유지된다. 검색 결과가 없으면
이름 없는 기존 구분선을 유지하고 `No matching transforms`를 표시한다.

작은 화면은 구분선 행이 없으므로 한정된 상세 영역에서 이름과 설명을 다음처럼 구분한다.

```text
Base64 Encode — Encode bytes using padded RFC 4648 Base64
```

터미널 너비가 부족하면 기존 `Paragraph` 줄바꿈과 잘림 규칙을 따른다. 변환 표시 이름과
등록 설명만 사용하며 새 메타데이터나 스타일 역할은 추가하지 않는다.

## 3. 변경 범위

- `src/tui/state.rs`: Picker `Up`·`Down` 선택값을 순환 계산으로 변경
- `src/tui/render.rs`: 일반 화면 제목 구분선과 작은 화면 이름·설명 구분 표시
- 상태·렌더링 단위 시험: 키보드, 마우스 휠, 검색 결과 0개·1개, 일반·작은 화면

README는 Picker의 세부 이동·상세 배치를 설명하지 않으므로 변경하지 않는다. 공개 CLI,
변환 레지스트리, 키 바인딩, 의존성도 변경하지 않는다.

## 4. 예외와 안전성

- 빈 검색 결과에서 길이 계산이 언더플로하지 않게 한다.
- 선택값은 항상 현재 필터 결과 범위 안에 둔다.
- 선택이 실제로 바뀔 때만 `mark_dirty`를 호출한다.
- 마우스 클릭으로 보이는 행을 고르는 기존 동작은 변경하지 않는다.

## 5. 검증

- 키보드: 첫 항목 `↑` → 마지막 항목, 마지막 항목 `↓` → 첫 항목
- 마우스 휠: 위와 같은 양방향 순환
- 검색: 결과 없음과 단일 결과에서 선택·dirty 상태 유지
- 렌더링: 일반 화면의 제목 포함 구분선, 작은 화면의 `이름 — 설명`
- 회귀: Picker 검색·추가·Backspace·클릭, 작은 화면과 `NO_COLOR`
- 전체: Format, 경고 금지 Clippy, 전체 잠금 시험, rustdoc

## 6. 제외

- PageUp·PageDown, Home·End 같은 신규 Picker 키
- 스크롤바와 애니메이션
- 범용 순환 목록 자료형
- Modal 크기와 변환 설명 데이터 변경
