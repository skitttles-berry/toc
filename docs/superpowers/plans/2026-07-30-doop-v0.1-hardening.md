# doop v0.1 안정화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Every behavior change follows superpowers:test-driven-development.

**Goal:** 독립 리뷰에서 확인한 v0.1의 자원 증폭, 렌더링 지연, 오류 표시, CLI 모호성, 플랫폼 검증 공백을 최소 변경으로 제거하고 v0.2 16진수 변환의 승인용 명세를 준비한다.

**Architecture:** 기존 단일 Cargo 패키지와 변환 등록 구조를 유지한다. TUI 입력 경계에서 크기와 줄 수를 제한하고, 상태 변화가 있을 때만 다시 그린다. 기존 오류형과 셸 검증 흐름을 확장하되 새 내부 계층이나 CI는 추가하지 않는다.

**Tech Stack:** Rust 1.97.1, Rust 2024 Edition, Clap 4.6.4, Ratatui 0.30.2, Crossterm 0.29.0, tui-textarea-2 0.12.1, unicode-width 0.2.2, Bash, Zsh, Docker

## Global Constraints

- `main` 브랜치에서 작업하며 기존 단일 패키지 구조를 유지한다.
- GitHub Actions, Workspace, 플러그인 구조, 실제 16진수 변환 구현은 추가하지 않는다.
- 프로덕션 동작 변경은 실패 시험을 먼저 확인한 뒤 최소 코드로 통과시킨다.
- 입력 검증, 오류 처리, 터미널 복원, 클립보드 안전 처리를 단순화하지 않는다.
- 관련 PRD, 설계, README는 코드와 같은 논리적 커밋에서 동기화한다.
- 구현하지 않는 항목과 Wayland 미검증 상태는 문서에 명시한다.

### Task 6: v0.2 16진수 변환 승인용 명세

**Files:**
- Create: `docs/prd/v0.2-prd.md`
- Create: `docs/superpowers/specs/2026-07-29-doop-v0.2-hex-design.md`

- [ ] 공개 식별자를 `hex-encode`, `hex-decode`로 고정한다.
- [ ] 인코딩은 임의 바이트를 소문자 16진수로 출력하며 접두사·구분자·줄바꿈을 추가하지 않는다.
- [ ] 디코딩은 ASCII 공백·탭·CR·LF만 무시하고 대소문자를 허용한다.
- [ ] `0x`, 콜론, 쉼표, 홀수 자릿수는 거부하며 잘못된 문자의 원본 바이트 오프셋을 보고한다.
- [ ] 디코딩 결과는 유효한 UTF-8만 성공시키고 그 외에는 기존 64바이트 16진수 미리보기와 전체 길이 정책을 재사용한다.
- [ ] 검사된 할당과 기존 입력·출력 한도를 적용하고 새 16진수 의존성을 추가하지 않는다.
- [ ] 구현 예정 파일은 `src/transforms/hex.rs`, v0.2 등록 변환 수는 정확히 8개로 명시한다.
- [ ] 구현하지 않는 확장 아이디어를 별도 절에 기록한다.
- [ ] 설계 문서를 사용자에게 제시해 승인받기 전에는 구현 계획이나 코드를 작성하지 않는다.
- [ ] Commit: `docs(v0.2): 16진수 변환 명세`
