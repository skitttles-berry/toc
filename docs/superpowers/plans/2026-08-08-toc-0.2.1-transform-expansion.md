# toc 0.2.1 TUI and Transform Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` and
> `superpowers:test-driven-development` task by task.

**Goal:** Refine the Pipeline/Output contract and expand the shared transform
registry from 8 to 24 independently implemented, fixed-behavior transforms.

**Architecture:** Keep `TransformFn`, the single static registry, the existing
pipeline policies, and the Smart/Text/Hex/Trace views. Add focused transform
modules and register them once so CLI commands, `--then`, the TUI Picker, and
Trace all consume the same definitions.

**Tech Stack:** Rust 2024, Ratatui, Crossterm, `base64`, `data-encoding`,
`html-escape`, `sha2`, `flate2`, Serde JSON.

## Global Constraints

- Public version is `0.2.1`; keep the current input/output limits and 32-step
  Pipeline limit.
- Preserve `TransformFn`, the one static registry, public
  `pipeline::execute` StrictText behavior, current views, keys not named here,
  clipboard behavior, status handling, zoom, and scrolling.
- CLI-internal execution uses the existing AllowBinary policy. Pipes and
  redirections receive raw bytes; an actual terminal still rejects non-UTF-8
  and dangerous control-byte output atomically.
- All expansion and decompression paths enforce the per-step output limit
  during allocation or writing and never return a partial result.
- Add no Recipe, categories, transform options, typed Artifact, new View,
  generic keymap, or framework layer.
- Use exact dependencies with minimal features: `data-encoding 2.11.1`,
  `html-escape 0.2.15`, `sha2 0.11.0`, and `flate2 1.1.9` with its pure-Rust
  backend.
- Preserve historical v0.1/v0.2 documents. Add v0.2.1 PRD and design files,
  and keep README behavior and verified test counts current.
- Do not copy Boop or CyberChef code. They are feature-discovery sources only.
- Preserve the user's untracked `.codex/` directory.

## Task 2: Add fixed text and web transforms

**Files:**
- Modify: `Cargo.toml`, `Cargo.lock`, `src/error.rs`, `src/transforms/mod.rs`
- Add focused files under `src/transforms/`
- Modify exhaustive error renderers/tests as required for compilation

Write failing unit tests first, then add internal implementations for:

- `base64url-encode`: RFC 4648 URL-safe alphabet, no padding.
- `base64url-decode`: ignore only ASCII space/tab/CR/LF; reject `=`, invalid
  alphabet, and non-canonical trailing bits.
- `base32-encode`: RFC 4648 uppercase alphabet with canonical padding.
- `base32-decode`: accept ASCII letter case and the same four ASCII
  whitespace bytes, require canonical padding, and reject non-canonical
  trailing bits. Add `InvalidBase32 { position: Option<usize> }` with a safe
  renderer.
- `html-encode`: escape only `&`, `<`, and `>` in HTML text context.
- `html-decode`: decode only exact semicolon-terminated valid named or numeric
  entities; leave malformed, missing-semicolon, and unknown entities intact.
- `rot13`: transform ASCII letters only.
- `url-defang`: replace exact lowercase `http://`/`https://` with
  `hxxp[://]`/`hxxps[://]`, then replace dots with `[.]`.
- `url-refang`: perform the exact inverse replacements.

Declare and unit-test the modules but do not register the new public IDs yet;
Task 5 performs the one registry/CLI integration. Enforce output limits before
allocation or while writing. Run focused tests, all library tests, Clippy for
touched targets, formatting, and `git diff --check`. Commit the logical change.

## Task 3: Add strict JWT decoding

**Files:**
- Modify: `src/error.rs`, `src/transforms/mod.rs`
- Add: focused JWT transform module and tests
- Modify exhaustive error renderers/tests as required

Write failing tests first, then implement internal `jwt-decode` behavior:

- Accept exactly three dot-separated compact JWS segments after trimming only
  the four supported ASCII whitespace bytes around the complete token.
- Header and payload use the same canonical unpadded Base64URL rules as Task 2
  and must each decode to a strict JSON object. Reuse the existing JSON parser
  and formatter policies, including duplicate-key/depth handling and retained
  key/token ordering.
- Validate the signature segment as canonical Base64URL but do not verify it;
  preserve the original segment string in output. An empty signature is valid.
- Emit two-space JSON in field order `header`, `payload`, `signature`,
  `warning`, with the exact warning `Signature not verified`.
- Add a safe public JWT-part error representation covering structure, header,
  payload, and signature without echoing token contents.
- Enforce the output limit while composing; return no partial output.

Do not register the public ID yet. Run focused tests, all library tests,
Clippy, formatting, and `git diff --check`. Commit the logical change.

## Task 4: Add SHA-2, deterministic Gzip, and line transforms

**Files:**
- Modify: `Cargo.toml`, `Cargo.lock`, `src/error.rs`, `src/transforms/mod.rs`
- Add focused hash, gzip, and line transform modules/tests
- Modify exhaustive error renderers/tests as required

Write failing tests first, then add internal implementations for:

- `sha256` and `sha512`: arbitrary bytes to lowercase hexadecimal with no
  newline, checked against known vectors.
- `gzip-compress`: level 6, `mtime=0`, OS=255, no optional fields, exactly one
  member, with bounded output writing.
- `gzip-decompress`: process every member, validate headers/CRC and trailing
  garbage, enforce the output limit while reading, and return `InvalidGzip`
  without partial output on malformed input.
- `sort-lines` and `remove-duplicate-lines`: UTF-8 only; recognize LF/CRLF,
  normalize separators to LF, preserve whether the input ended in a newline,
  sort in Unicode code-point order, and retain the first occurrence for
  deduplication. Empty input remains empty. Reject more than 1,000,000 logical
  lines with `TooManyLines { limit }` before result construction.

Do not register public IDs yet. Use `sha2 0.11.0` without default features and
`flate2 1.1.9` without defaults plus `rust_backend`. Run focused tests, all
library tests, Clippy, formatting, and `git diff --check`. Commit the logical
change.
